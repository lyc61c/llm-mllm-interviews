## 视频采样与时序

<a id="omm-001"></a>
### OMM-001 · 视频 VLM 怎样构建与训练，帧数和 token 预算如何控制？

**L2** · 腾讯

#### 答案

视频 VLM 不只是把图片模型多喂几张图，还要保留事件的顺序和时间。常见做法是抽帧后用逐帧视觉编码器，或用时空编码器提取特征，再通过时序聚合和连接器接入语言模型，让它根据视频和问题回答。

首先控制采样。均匀抽帧适合覆盖整段时间，按视觉变化选帧可以减少重复，长视频也可先分段检索再读相关部分。例如问视频主题与问“手何时碰到按钮”，需要的采样密度不同。相邻帧通常重复，盲目增加帧数很费资源，却仍可能错过短暂事件，因此采样后必须保存真实时间戳，而不只是新列表中的帧号。

总输入预算大致由帧数、每帧视觉 token 与文本长度决定。超过预算时可降低分辨率、减少帧数或压缩特征，但这些操作分别损害细节、事件覆盖或局部信息，应在短事件、动作顺序和时间定位任务上验证。图像与视频联合训练还要统一表示、模板和位置协议。

监督取决于任务：视频与文字匹配可做对比学习，描述和问答可做文本生成，动作识别可用分类。不存在所有视频预训练都只用一种 loss 的答案。我会先说明任务与数据，再解释网络、时间表示和成本，最后用对应评测验证采样与压缩是否保留了真正需要的证据。

#### 易错点

- 抽帧序号不能代替真实时间，尤其对可变帧率视频。

#### 追问

- 一分钟短视频和两小时视频如何设不同预算？

<a id="omm-002"></a>
### OMM-002 · 视频时间位置编码为什么要考虑真实时间与 FPS？

**L2**

#### 答案

视频时间编码需要真实时间，因为“第几帧”不一定表示“第几秒”。不同 FPS 或采样密度下，相同帧序号对应的时间间隔不同，只记帧号容易把动作速度和事件持续时间混淆。

例如同一段10秒视频，一次抽10帧，一次抽20帧，抽样列表里的第5帧代表的时刻就不同。输入应记录每帧在源视频中的时间并统一单位；可变帧率视频更应读真实时间戳，不能套固定平均 FPS。Qwen2.5-VL 把时间位置关联到绝对时间，并用动态 FPS 采样训练模型适应不同采样密度。

时间坐标提供线索，但模型还要通过事件定位等监督学会使用它。评测需看动作内容、起止时刻、时间误差和短事件召回，而不是只确认输出有几位小数。抽样没看到的动作不会因时间编码精确就自动出现。

若视频倍速、裁剪或拼接，要明确标签用源视频时间还是处理后时间，并同步调整映射。先保证预处理与标注一致，再讨论位置编码能带来什么提升。

#### 易错点

- 时间编码改进不能保证模型自动精确定位所有事件。

#### 追问

- 视频被倍速播放时哪些标签需要调整？

<a id="omm-003"></a>
### OMM-003 · 长视频理解怎样压缩视觉 token，又有什么代价？

**L3** · 美团 / 快手

#### 答案

长视频压缩视觉 token 的目标，是在有限上下文里保留与任务相关的证据。可以先减少重复帧或做空间池化，也可以用时空连接器汇总特征、分段摘要或检索相关片段。VideoLLaMA 2 的时空连接器就是联合处理空间和时间的一种例子。

压缩方法要按问题选。主题总结可以接受较粗摘要，手部操作、瞬时事件和时间顺序则需要更高保真。简单平均全部帧可能把先后关系抹掉，分段摘要也应保留时间边界并能回查原片段。文本说得流畅，不表示视觉证据没有丢失。

动态剪枝还要看发生在哪一层。在视觉编码或连接器前后删 token，可以节约较多后续计算；在语言模型深层才删，前面的编码成本已经花掉。冗余方法找相似空间或跨帧特征；任务相关方法用文本 Q 与视觉 K 的关联挑证据；V2Drop 则看同一个视觉 token 在相邻语言层之间变化多少，逐步保留变化较大的位置。这里是跨层表征变化，不是跨帧距离，也不需要显式完整注意力矩阵；变化小只是启发式，不是无损证明。

手框等 ROI 先验可以与任务评分、冗余结合，但漏检时要有最低保留预算和回退。移植 LLaVA 到 Qwen-VL 还需重新识别视觉 span、动态网格与 merger、帧位置和 M-RoPE，不能照搬固定576个 token 的偏移。FlashAttention 通常不返回完整权重，强行读取可能回退到高显存实现；只加 mask 而不缩短矩阵，也未必真的加速。

比较时固定模型、帧数、分辨率、生成长度、硬件、精度和内核，计入选择器与 ROI 的额外开销，报告端到端延迟、峰值显存及手部和短事件质量。最终 token 数相同，不同剪枝层仍可能总成本不同；还应对齐数据、模板与代码版本。若方法要用于生成网络，其输出 latent 网格能否恢复需另行验证。

#### 易错点

- 平均所有帧特征会丢失部分顺序信息。

<a id="omm-004"></a>
### OMM-004 · 视频定位如何输出准确时间点，怎样评估？

**L2** · 腾讯

#### 答案

视频定位是给定一句描述，找出它在视频里发生的起止时间；这比只回答视频内容多了一个时间坐标任务。例如“人打开门”回答正确，但把时间标成视频开头，仍是定位失败。

输入端先保留采样帧的真实 PTS 或秒级时间戳，训练端提供事件区间或时间标签，让模型学会内容与时间对应。长视频可先稀疏采样找到粗候选，再在候选区间密集采样细化。若事件只在未采样瞬间发生，输出更多小数位也不能增加证据。可变帧率尤其不能直接用帧号除以一个固定 FPS。

常见指标是时间交并比 tIoU 和指定阈值下的召回。公式中预测区间为[s_p,e_p]，真值为[s_g,e_g]，交集长度 I 是较早结束时间减较晚开始时间，并与0取最大值；再除以两个区间合并后的长度。例如真值2到6秒、预测3到7秒，交集3秒、并集5秒，tIoU为0.6。公式要求有效非零时长区间。

还应检查起止顺序、视频边界与时间映射，并分别看短事件、重复动作和多段有效答案。Moment-DETR 的区间定位与显著性是不同目标，也要分开报告；多个正确片段时需先规定匹配和召回协议，不能把 tIoU 当逐帧分类准确率。

```math
\begin{aligned} I&=\max\left(0,\min(e_p,e_g)-\max(s_p,s_g)\right)\\ \mathrm{tIoU}&=\frac{I}{(e_p-s_p)+(e_g-s_g)-I} \end{aligned}
```

#### 易错点

- 不要把时间 IoU 当作逐帧分类准确率。

#### 追问

- 有多个有效片段时怎样定义召回？

### OMM-017 · 开放场景下如何跟踪多个视频实例，并处理遮挡和镜头切换？

**L3** · 腾讯

#### 答案

开放场景多实例跟踪，先确定“跟同类所有对象还是指定对象”，以及身份只需在单镜头一致，还是要跨镜头保持。检测回答“现在有哪些对象”，跟踪回答“它们是不是之前那些对象”，这两步不能混淆。

例如 SAM3 按概念检测当前实例，记忆跟踪器传播已有掩码，再按重叠与匹配关系更新轨迹；新检测可建立新轨迹，用时间确认和重复轨迹抑制减少误检，必要时以高置信检测重新提示。记忆更新要谨慎，错误掩码反复写入会把漂移越放越大。遮挡、目标离场和场景变化也需要不同恢复条件，不能全部立即删 ID。

镜头切换是额外系统设计。我会检测硬切或渐变，并区分快速摇镜；确定切换后重新检测，不把上镜头的空间运动与掩码直接传播到新画面。误报切点会破坏身份连续性，所以切点准确率和召回也要单独测，不能把这项策略冒称 SAM3 自动内置的能力。

若要跨镜头身份，再建立外观特征、轨迹摘要与全局关联，根据外观、时间和场景约束匹配；证据不足就用新 ID 或待确认状态。同为“红色汽车”不意味着同一辆车，掩码传播也不保证任意重识别。评估要同时看掩码质量、漏检误检、身份切换、关联指标如 HOTA 及延迟，而不是只报单帧 IoU。

#### 易错点

- 重检测后为相同类别分配旧 ID，会把不同实体错误合并。
- 清理跨镜头空间记忆是工程策略，不能冒称 SAM3 论文内置的自动切镜头机制。
- 遮挡、目标离场和场景切换需要不同恢复条件，不能统一当作删除目标。

#### 追问

- 快速摇镜与硬切如何区分，切点误报会怎样影响跟踪？
- 新增实例确认延迟与实时响应怎样取舍？

<a id="omm-024"></a>
### OMM-024 · 1–10分钟第一人称操作视频只有粗 caption，如何切子动作并用于时序训练？

**L3** · 美团

#### 答案

只有一段粗caption，不能直接知道几分钟视频里每个子动作的边界。例如“做早餐”可能包括拿杯子、倒水、搅拌，但文字没有告诉我们哪一步真发生、顺序怎样，更不能把“做早餐”复制到每个短clip当精确标签。

我会保留源时间戳和视频级目标，先用多尺度滑窗找候选，再结合手物接触、物体状态与运动特征细化。让视频VLM在实际候选片段上输出起止时间、动词、对象、前后状态、证据帧和置信度，再合并重复、检查顺序与覆盖，人工抽审关键边界。第一人称镜头和手会同时运动，切镜头或画面变化不必是子动作边界，低置信接触也不能补成确定事实。

Ego4D 区分整段summary与带时间窗口的动作narration，只有粗summary时就应承认弱监督。少量人工时间点或边界能提供重要锚点；CliMer等使用narration与粗定位的方法，也不能证明仅一段总描述就能恢复精确边界。离线伪标签便于缓存与复核，在线按问题细采样更灵活却更贵，可以结合为离线候选库加在线检索细化。

理解模型可用可信clip与描述对齐、动作分类或时间定位；生成模型可用局部动作条件与短clip继续去噪/速度回归，并保留可部署的前段上下文学习衔接。低置信伪标签降权，不能冒充逐帧真值，也不能把未来真实画面泄漏给只能看过去的生成条件。

训练测试按视频与操作隔离，避免相邻clip跨集合。用人工边界、重复动作和未见操作评估定位，再看生成动作完成与跨片段连续性；两次倒水不能为了caption简洁合成一段虚假的长动作。描述流畅只是语言质量，不等于拆分正确。

#### 易错点

- CliMer等粗时间戳方法仍使用narration和粗时间定位，不能外推成仅一个整段caption就能恢复精确动作边界。
- 手物接触可能不可见，低置信度必须保留，不应让模型补成确定事实。
- 未来视频生成若依赖前段上下文，训练不得把后段真实画面泄露给可部署条件。

#### 追问

- 同一视频中两次倒水如何避免伪标注合并为一个长动作？
- 只新增少量人工监督时，标动作时间点、完整边界或长caption怎样选？

<a id="omm-019"></a>
### OMM-019 · Wan2.1 有哪些版本，视频生成架构是什么，如何选择并验证原生微调基线？

**L2** · 快手 / 百度

#### 答案

介绍 Wan2.1，我会先明确文字生成视频 T2V，还是参考图生成视频 I2V，再说明 checkpoint 和分辨率。核心 T2V 有1.3B和14B：1.3B官方推荐480P，14B支持480P/720P；核心 I2V 是14B并提供两种分辨率权重。1.3B不是结构上绝对不能生成720P，而是该分辨率训练有限，官方推荐更稳定的480P。

模型由 Wan-VAE、umT5 文本编码器和视频 DiT 组成。VAE 把视频压成16通道 latent，通常按时间、高、宽约4×8×8压缩；首帧单独处理，若有4k+1帧，latent 时间长度是k+1，不是简单把所有帧除以4。DiT 把 latent 再切时空 patch，用注意力与时空位置编码学习运动，通过交叉注意力读取文本条件。因果 VAE 约束的是编码时的时间依赖，不表示 DiT 按帧自回归生成。

Wan2.1-I2V 有两条参考图路径。首帧经过 VAE 后，与重排 mask 和待去噪 latent 在输入通道拼接；CLIP 图像特征投影后又提供独立图像 K、V，与 umT5 文本分支共享视觉 Q 做分离交叉注意力，再合并结果。前者提供空间结构，后者提供图像表征，不能都描述成普通文字 token。

基础训练是 Flow Matching。这里沿论文约定，x_0是噪声、x_1是真实 latent，插值 x_t=(1−t)x_0+tx_1，目标速度 x_1−x_0，采样从0到1；这与某些 scheduler 的0数据、1噪声定义相反，速度和积分方向需同步转换。论文先低分辨率图像预训练，再联合更高分辨率图像视频，生成训练固定 VAE 和文本编码器。主干参数标签不包含这些模块、激活和优化器的全部显存。

选型时，纯文字任务先看 T2V，首帧条件先看对应 I2V，1.3B可以作较低成本消融。严格姿态或轨迹控制可能要新分支，但先建立冻结原模型、LoRA或原生 DiT 微调基线，再证明结构必要性。固定数据、条件、分辨率、帧数、采样与算力，比较控制、画质、时序、泛化和成本；没做过的实验就说明待验证，不能把官方演示数字讲成个人训练结果。


### OMM-020 · Wan2.2 的高噪与低噪专家怎样切换，SNR、时间门限和 LLM MoE 有什么区别？

**L3** · 百度

#### 答案

Wan2.2 的 A14B 用两个生成专家分别处理高噪和低噪阶段，可以理解为先搭整体布局，再细化细节。T2V-A14B 与 I2V-A14B 总参数约27B，每一步激活约14B；TI2V-5B 是 dense 模型，不能把所有2.2都说成同一双专家结构。A14B仍用 Wan2.1-VAE，5B版本才用更高空间压缩的 Wan2.2-VAE。

这里的专家切换由去噪时间决定，一步选一个专家处理整段 latent，不是语言 MoE 那种每个 token 用可学习 router 挑不同 FFN，也不是轮流处理视频帧。官方推理比较 scheduler 的当前 t 与 bN：大于等于门限用高噪专家，否则用低噪专家。所核对默认 N=1000，T2V的b=0.875、I2V的b=0.900，对应875和900的时间门限。

实现中接近1表示噪声、接近0表示数据，所以从高噪走向低噪。SNR 是信号功率与噪声功率之比；公式采用独立、单位方差数据与噪声的线性混合，噪声比例 s 越大，(1−s)²/s² 越小。高噪早期 SNR低，后期细化 SNR高。代码用预设时间门限，不是每一步读取图像再估算 SNR 做学习路由。

采样时间经过 shift 后，落在门限两边的实际步数会变化，所以不能把40步机械切成“35步高噪、5步低噪”；视频帧、噪声时间和循环次数是三件事。更改 solver、shift、门限或指导强度时，需要重新验证覆盖与切换处质量。

两套专家仍要存权重，每步14B不等于总显存只存14B。全部驻留更占显存，CPU offload 可以降低驻留，却增加搬运。微调还应说明训练哪个专家、采样哪些噪声区间；只训低噪不保证布局和复杂运动随之改善，默认门限也不必然是所有任务最优值。

```math
\begin{aligned}E(t)&=\begin{cases}E_{\mathrm{high}},&t\ge bN\\E_{\mathrm{low}},&t\lt bN\end{cases}\\x_s&=(1-s)x_{\mathrm{data}}+s\epsilon,\qquad 0\lt s\lt 1\\\mathrm{SNR}(s)&=\frac{(1-s)^2}{s^2},\qquad\frac{d\,\mathrm{SNR}}{ds}=-\frac{2(1-s)}{s^3}\lt 0\end{aligned}
```

#### 易错点

- TI2V-5B是dense，不能把A14B的双专家、参数与VAE配置套到全部2.2版本。
- 大去噪时间表示高噪低SNR；视频帧、噪声时间和循环步数不同。
- 本式SNR依赖独立、单位方差的线性路径，换路径或缩放就要重算。
- 每步激活14B不表示系统只存14B权重，驻留、offload和并行还影响成本。

- 为什么T2V与I2V默认门限不同，如何做门限扫描而不把训练集当评测？
- 只训练低噪专家时，能否保证主体布局或复杂运动能力随之改善？

### OMM-021 · 视频生成怎样评测时序和动作、设计多维奖励，并校准 Qwen-VL 打分？

**L3** · 美团 / 快手

#### 答案

视频生成评测要把“画得好”“动得对”“按要求完成动作”分开。相邻帧 CLIP 相似度只说明外观接近，静止或复制帧也能很高；真实拿起杯子、转动镜头反而可能降低相似度，所以它不能独自证明动作完成。

我会把动作写成可观察的步骤和终态，例如“抓住杯子并移到桌面”，分别检查对象、接触、位移和结果，再评主体/背景一致性、闪烁、平滑和手部质量。VBench 提供多维指标，但运动大小应符合任务，不是越大越好，也要排查静态视频拿高分的漏洞。

FID 比較图像特征集合，把视频帧打乱后逐帧 FID 可能不变，不能检验顺序；FVD 用视频特征比较两组分布，可以包含时序信息，却不是某条视频的动作正确率。两者要固定网络、抽帧、FPS、长度、分辨率、样本量和预处理。LPIPS 是图像对的感知距离，重建任务要有对齐参考；开放生成不能随便拿一段真值强行配对，距离低也可能只是视频不动。

奖励组合先统一方向，让每项越大越好，距离和误差需取负或做下降映射。公式中 r_k 是分项分数，μ_k、σ_k 来自固定校准集，w_k 是非负权重，总和为1；这一步是统一不同量尺，不是 GRPO 在同条件组内算相对优势。权重应通过独立人评验证，保留分项结果，避免好画质抵消动作没完成。

Qwen-VL 评分要固定模型、帧与时间戳、rubric和输出格式，给0、5、10分准备人工锚点，再看重测稳定性、人评排序相关性及静止、倒序、畸形手等难例。解析失败记无效，抽帧没看到的细节不能靠提示补回来；VideoScore 这种专门人评训练的评分器也不等同通用模型的prompt打分。最后用同条件、同采样预算、多种子盲评 SFT/RL 的动作、质量和多样性。训练奖励上涨而独立质量下降，就要检查模型是否在钻评分规则的空子。

```math
\begin{aligned}r_{\mathrm{sim}}&=\frac{1}{F-1}\sum_{j=1}^{F-1}\frac{f_j^\top f_{j+1}}{\lVert f_j\rVert_2\lVert f_{j+1}\rVert_2}\\ R(v,c)&=\sum_{k=1}^{K}w_k\,\frac{r_k(v,c)-\mu_k}{\sigma_k+\epsilon},\qquad w_k\ge0,\quad\sum_k w_k=1\end{aligned}
```

#### 易错点

- 相似度奖励要求至少两帧、非零特征范数；静止视频可达高分，但不表示目标动作正确。
- 评分锚点和校准需要独立人工样本；同一裁判既训练又验收会隐藏偏差。
- 稀疏抽帧看不到的手部接触或畸变不能靠裁判提示词恢复。
- FID/FVD是集合分布指标，不能把一条视频的分数当标准实现结果；采样协议和集合规模须一致。
- LPIPS低表示感知上近，不等于动作正确；对合法开放生成用任意真值配对可能误罚多样性。

- “打开抽屉”怎样分别验证动作、终态和手部几何？

### OMM-022 · 视频生成为何在 SFT 后做 GRPO，batch size=8 时怎样采样、打分和更新？

**L3** · 美团 / 快手

#### 答案

视频 SFT 先通过去噪或速度回归学会合理场景与运动，GRPO 再用同条件下多条候选的结果奖励调整偏好，例如提高动作完成率。它不是给像素做文本回答交叉熵；RL 也不能替代缺失的运动先验，前提是能生成有差异的合理候选、奖励能可靠区分它们。

先问清 batch size=8 指什么：8个条件、8条视频、每条件8个候选，还是训练 microbatch。公式中 P 是条件数，G 是每条件候选数，共生成 PG条；若8是总候选，可以是2个条件各4条。必须收齐同条件组再算均值、标准差与相对优势，跨卡也不能拆乱group ID。评分可以异步进行，收齐本轮buffer就更新，不必等全部6000条数据都生成。示式用总体标准差，其他框架需核对；G至少2，奖励全相同则没有相对信号。

视频中的帧轴与去噪时间轴不同。每次去噪的动作是更新整段 latent，而不是生成一帧。做概率比 RL 还需定义合法随机转移，保存状态、下一状态、时间、旧log-prob和采样设置。公式的ρ是同一转移在新旧策略下的概率比，用对数差再指数计算；本题0数据、1噪声，时间从t到t−h。纯 ODE 转移是确定性的，不能硬套普通高斯密度或照抄语言token概率比。Flow-GRPO原实验主要是图像，迁移视频需核对随机scheduler、指导强度及高维概率归约。

最终视频只有一次奖励，也能更新前面的随机去噪步：基础 score-function 梯度把终态奖励与各转移的log-prob梯度相乘，不需穿过黑盒裁判或整条采样链反传。公式末行说明的是这个未裁剪期望梯度；GRPO另外用组优势、旧策略比率、clip和KL构造代理目标，不能宣称仍完全无偏，也不能把同一终态奖励解释成每一步的精确因果贡献。对可微奖励全链反传是另一种 pathwise 方法，显存与目标不同。

实现先检查同策略同轨迹ρ≈1、转移方差非零、时间与预测类型一致、完整联合密度与逐维平均归约一致，再检查 LoRA 梯度、零方差组、有效评分和旧样本滞后。clip不能保证任意旧样本安全。microbatch与梯度累积要看真实reshape，不能只改配置字段；帧数和采样步数可按质量成本曲线选，patch大小则常属于固定架构，随意改可能要适配权重。多少步见收益应由固定验证集曲线回答，不能报通用数字。

```math
\begin{aligned}N_{\mathrm{rollout}}&=PG,\qquad G\ge2\\ \bar R_p&=\frac1G\sum_{i=1}^G R_{p,i},\quad s_p=\sqrt{\frac1G\sum_{i=1}^G(R_{p,i}-\bar R_p)^2},\quad\hat A_{p,i}=\frac{R_{p,i}-\bar R_p}{s_p+\epsilon}\\ \rho_{p,i,t}&=\exp\!\left[\log\pi_\theta(x_{t-h}\mid x_t,t,c_p)-\log\pi_{\mathrm{old}}(x_{t-h}\mid x_t,t,c_p)\right]\\ \nabla_\theta J&=\mathbb E_{\tau\sim\pi_\theta}\left[R(\tau)\sum_t\nabla_\theta\log\pi_\theta(x_{t-h}\mid x_t,t,c)\right]\end{aligned}
```

#### 易错点

- 每帧不是一次去噪动作；一个去噪转移更新整段视频latent。
- 黑盒奖励不用经过裁判反传；对可微奖励全链反传是另一种方法。
- 旧样本过多会偏离当前策略，clip不能保证任意滞后都安全。
- 核对真实reshape与梯度累积，不能只改train.batch_size字段就认定microbatch已变。
- 联合latent log-prob求和与按维平均尺度不同，采样、训练、clip和KL的归约必须一致。
- 末行只是基础未裁剪策略梯度，不是完整GRPO损失，且要求合法随机转移密度。
- GRPO同组中心化与标准差缩放改变了目标，不能宣称与原期望奖励梯度完全无偏等价。
- 帧数、采样步数与架构patch大小不同，改patch可能需要权重适配和训练。

### OMM-023 · 视频生成 RL 的 CLIP/Qwen-VL 评分如何加速，多模型显存和训练耗时怎样估算？

**L3** · 美团 / 快手

#### 答案

视频 RL 的评分提速，要先拆清时间花在哪里：生成去噪、VAE解码、取帧、评分排队、奖励模型前向，还是策略更新。“在线奖励”通常指新生成的视频即时评分，评分器本身可以冻结，并不意味着它也在训练。

固定条件文本的embedding、离线数据伪标注和同一视频可复用的帧特征可以缓存，但缓存键必须包括内容、模型、提示、抽帧与预处理版本。策略更新后生成的是新视频，不能拿旧视频奖励顶替。可按分辨率和帧数组批、复用解码帧与CLIP特征、关闭评分器反向图、减少无关输出，或放到独立GPU与生成阶段流水重叠。线程异步提交不代表同卡GPU真的能并行。

昂贵 Qwen-VL 裁判可考虑蒸馏成小评分器，但要在独立人评与难例上确认排序；量化奖励器也要重新检查分数。少抽帧或降分辨率虽然快，却可能看不到手指或短动作，必须一起测质量。Flow-GRPO 图像代码的异步奖励和收齐buffer后更新，只是一种调度示例，不是所有视频系统的统一流程。

显存应加上生成权重、优化器、更新激活、rollout latent轨迹、VAE、各评分器权重和它们的输入峰值。同卡驻留容易实现却会竞争；分卡增加传输与排队；offload降低驻留但增加搬运。梯度累积只减少更新microbatch的峰值，不能消掉轨迹缓存或奖励器权重。概率转移式 RL 可先无梯度采样，再按步骤或子批重算前向，不必一直保存全链反向激活，但方法要求的状态、动作和旧概率仍要保存。

6000条数据不足以直接报小时数，还需G、帧数、分辨率、采样步数、轮数、复用次数、卡型与并行方式。我会用代表性小批实测各阶段耗时与峰值，再按真实轮次外推。公式里 U是更新轮次，其余是生成、解码评分、更新、评测及保存重试时间；简单相加仅适用于串行调度，存在重叠时应按关键路径估算，而不是把论文速度当自己的训练时间。

```math
T_{\mathrm{total}}\approx U\big(T_{\mathrm{generate}}+T_{\mathrm{decode/score}}+T_{\mathrm{update}}\big)+T_{\mathrm{eval}}+T_{\mathrm{save/retry}}
```

#### 易错点

- 缓存键必须覆盖视频内容和评分协议；策略更新后新视频不能复用旧视频的奖励。
- 流水重叠只有资源与依赖允许时才产生收益，线程异步提交不保证同卡GPU计算真正并行。
- 梯度累积降低更新microbatch峰值，不会自动消除rollout缓存或评分器权重占用。

- 一轮rollout有大量latent，哪些必须保存以重算同一动作的log-prob？

### OMM-025 · 第一人称视频的相机抖动如何建模，camera pose 条件怎样注入生成网络？

**L3** · 美团

#### 答案

处理第一人称抖动，先区分相机移动、独立物体运动与不希望保留的高频抖动。光流同时包含这些变化，不能直接当可靠camera pose。可以结合相机内参和姿态估计建立轨迹，但快速运动、遮挡、滚动快门和单目尺度不确定都要检查。

坐标约定先统一，最好以首帧作为相对锚点，明确外参是相机到世界还是世界到相机。抽帧要同步时间，裁剪、resize也要变换内参，否则同一组数字已经不对应当前图像。条件可以编码成每帧时序token，再用交叉注意力或调制送入生成网络。

更显式的方式是每个像素对应一条相机射线。公式里 K是内参，R是相机到世界旋转，o是相机中心；先用K的逆把像素[u,v,1]反投影成方向，再旋转并归一化得到d，最后用[o×d;d]形成6维 Plücker 射线表示。平移o作为射线起点参与力矩，不是直接加进方向向量。CameraCtrl把射线序列送入camera encoder，再把多尺度特征注入时序注意力；迁移到DiT时需要另外设计、训练和验证条件token或adapter，不能照抄成现成接口。

有pose条件只代表模型有机会区分视角与主体运动，不保证恢复模糊和遮挡几何。若想稳定视频，可提供可信平滑轨迹，但不能把任务需要的转头也滤掉。我会在同场景比较无条件、原轨迹、平滑和扰动轨迹，分别看位姿遵循、手物操作和时序画质，并把pose估计误差与生成控制误差分开，也检查条件分支是否只记住训练外观。

```math
\begin{aligned}d_{t,u,v}&=\frac{R_tK_t^{-1}[u,v,1]^\top}{\lVert R_tK_t^{-1}[u,v,1]^\top\rVert_2}\\ p_{t,u,v}&=[o_t\times d_{t,u,v};\ d_{t,u,v}]\in\mathbb R^6\end{aligned}
```

#### 易错点

- 本式R是相机到世界旋转、o是相机中心；另一种外参约定必须先转换。
- 姿态估计不是真值，应把估计误差与生成条件遵循误差分开。
- 改变FPS、顺序或裁剪后，要同步时间和内参，不能继续用旧条件。

#### 追问

- 视频水平翻转后，camera ray map和图像内参怎样同步处理？
- 平滑轨迹使手物操作看起来不对，怎样区分相机条件冲突和生成先验不足？

<a id="omm-026"></a>
### OMM-026 · 手部小目标扭曲模糊如何处理，逐帧 YOLO 手框怎样作为视频生成条件？

**L3** · 美团

#### 答案

手部模糊和变形，先找发生在哪个环节。原图手很小、抽帧错过接触、VAE压缩后只剩几个latent格、训练姿态不足，都会造成问题。已经消失的细节，单靠RL奖励很难补回，所以先保证输入与基础生成能力，再调偏好。

SFT可以用清晰且覆盖不同姿态、接触和动作的手物片段补先验，同时保留全局操作上下文，增加局部高分辨率或手部监督。真实快速运动本来可能模糊，不能把它们全部删掉而改变任务分布。模型能产生合理候选后，再用可靠几何、接触和时间奖励做RL，并固定预算比较收益。

逐帧YOLO手框先明确xyxy还是xywh，再变换到当前裁剪/缩放后的坐标。公式中W、H是当前图像宽高，归一化框b与手或对象语义embedding、时间embedding和置信度q一起，经MLP生成条件向量；框位置可用Fourier特征φ编码。还要携带左右手或track ID、缺失mask，处理多手、抖动和遮挡。可借鉴GLIGEN的框条件token，也可用时空mask、adapter或ROI局部分支，但视频融合与身份保持是需要训练验证的扩展，不是原图像方法自动具备。

框只说明粗位置和尺度，不能保证五根手指、关节方向和真实接触。这些问题需要更丰富的关键点、姿态或关系监督。训练若用未来真值视频检测的手框，推理也要有用户轨迹、规划器或预测器提供对应条件，不能读取尚未生成的真值帧，否则条件不可部署。

评估同时看手部细节、动作完成和时序一致性，避免奖励只喜欢静态大手。若用手框保护视觉token，还应保留交互对象、背景和动作前后帧的最低预算；漏检时回退，缺失框不代表没有手。注意力小也不代表手部无用，最后要用实际延迟与任务错误确认取舍。

```math
\begin{aligned}\tilde b_{t,k}&=(x_{\min}/W,\ y_{\min}/H,\ x_{\max}/W,\ y_{\max}/H)\\ h_{t,k}&=\mathrm{MLP}\big([e_{\mathrm{hand},k};\ \phi(\tilde b_{t,k});\ e_t;\ q_{t,k}]\big)\end{aligned}
```

#### 易错点

- 先确认手框是xyxy还是xywh，再按同一图像变换归一化。
- GLIGEN原工作面向图像，视频时间与身份融合是需训练验证的扩展。
- 缺失框不证明没有手，框也不能代替手部几何和动作监督。

- 某帧左右手框交叉，如何保持条件身份而不把两只手交换？

<a id="omm-005"></a>
### OMM-005 · Whisper 的输入、架构和多任务接口是什么？

**L1**

#### 答案

Whisper 是编码器—解码器式语音模型。它先把音频变成 log-Mel 频谱，也就是把声音在各时间点、各频率上的能量用对数尺度表示，再由编码器提取声学特征，文本解码器逐 token 输出转写、翻译或时间戳。

任务和语言通过特殊 token 指定。转写保留原语言内容，原始多语言 Whisper 的翻译任务则把非英语语音译成英语，不能理解成任意目标语言翻译。解码器不仅看声学特征，还依赖此前输出，所以它能利用文本上下文，同时也有串行生成成本。

原始模型以30秒音频段训练。长音频要分窗、对齐时间，并处理边界处半个词、窗口重叠造成的重复、遗漏及上下文传递。窗口之间不能简单无条件拼接转写，也不能因此把原始 Whisper 视为零延迟流式识别器。

我会分别评测正常语音、静音、音乐和强噪声。后几类可能触发错误转写或语言先验补词，业务还要结合端点检测、无语音判断和分窗策略。架构支持时间戳，不表示每个词都必然精确定位，仍需对齐与误差评估。

#### 易错点

- 转写保留源语言，翻译与转写并非同一任务。

#### 追问

- 分窗边界落在词中间时怎样处理？

<a id="omm-006"></a>
### OMM-006 · WER 怎样计算？为什么中文 ASR 常同时报 CER？

**L1**

#### 答案

WER 是语音识别的词错误率：先把预测与参考文本对齐，数替换、删除和插入，再除以参考词数。公式里的 S、D、I 分别是这三种错误，N_ref 是参考词数，不是预测词数。

例如参考有10个词，预测替换1个、漏掉1个、额外插入1个，WER就是3/10，即30%。插入很多时，分子可能超过参考长度，因此 WER 可以超过100%，不需要强行裁到1。空参考和静音样本如何计分则要提前规定。

中文没有天然空格分词，“研究生物”怎样切词会影响 WER，所以常同时报 CER 字符错误率，以字符作为对齐单位。CER也需要统一标点、数字、繁简等规范；“十二”和“12”含义相同，是否归一化要按业务协议确定，不能为了好看随意改测试答案。

整个语料的 WER 应先把错误数和参考长度汇总再相除，而不是无条件平均每句百分比，否则一个两词短句会被赋予与长句相同权重。业务还应单独看姓名、金额、地址等关键实体，因为平均错误率相同的系统，实际可用性可能差很多。

```math
\mathrm{WER}=\frac{S+D+I}{N_{\mathrm{ref}}}
```

#### 易错点

- 不要无条件平均每句 WER，短句会被过度加权。

#### 追问

- 数字格式不同但含义相同如何归一化？

<a id="omm-007"></a>
### OMM-007 · CTC 与自回归语音解码有什么区别？

**L2**

#### 答案

CTC 与自回归语音解码的区别，主要是怎样对齐音频和文字，以及是否逐词依赖已生成文本。CTC 在每个声学时间步给出字符或 blank 概率，再把所有能折叠成正确文本的对齐路径概率加起来；自回归解码则一步一步预测下一个文本 token。

音频帧比文字长得多，所以同一句话可能有多种对齐方式。CTC 用 blank 表示该时刻不输出标签，折叠时先合并相邻重复标签，再移除 blank。比如“a blank a”可以得到“aa”，而相邻两个“a”会合成一个“a”，所以重复字符需要足够时间步和分隔。公式中的 π 是一条帧级路径，B 是折叠操作，y 是目标文本，损失对所有合法路径求和后取负对数。

CTC 的输出形式不显式依赖前一个已生成字符，帧级计算更易并行，也可以配合外部语言模型解码；其声学编码器本身仍可能利用上下文，不能说完全没有语言信息。自回归模型更直接利用文本历史，容易统一转写、翻译等任务，但输出有串行成本，也可能受到语言先验误补。

选择时要结合实时性、对齐假设与任务范围。CTC 通常假设单调对齐，目标很长或有重复字符时输入步数要足够；自回归则要处理生成长度、结束条件和错误累积。不能仅凭一个损失名字就判断整个系统的延迟与质量。

```math
\mathcal L_{\mathrm{CTC}}=-\log\sum_{\pi:\,B(\pi)=y}\prod_t p(\pi_t\mid x)
```

#### 易错点

- CTC先合并相邻重复，再移除blank；交换顺序会把重复字符算错。

#### 追问

- 为什么重复字符会增加 CTC 的最小输入长度？

<a id="omm-008"></a>
### OMM-008 · 音频连续特征与离散 codec token 分别适合什么？

**L2** · 腾讯

#### 答案

连续音频特征与离散 codec token 更偏向不同目的。连续特征常用于识别和理解，让下游模型读取语义、节奏与声学信息；codec token 则把波形压成一串离散索引，方便生成后再解码还原声音。它不是文字 token，也不保证只包含语义。

例如 log-Mel 或波形编码器可输出帧级连续向量，再用于 ASR、声音分类或跨模态匹配，监督分别可能是文本生成、CTC 或对比损失。音频 codec 主要关心重建与码率；残差向量量化用多个码本逐层编码剩余误差，增加码本通常能保留更多细节，也增加存储和生成预测负担。低码率虽然省 token，却可能丢失音色或细节理解所需的信息。

比较时，我会同时看时间帧率、码本数量、码率、解码延迟、可懂度、音色和失真，而不是只看向量是否离散。理解任务与生成任务对信息保留的要求不同，编码形式、跨模态对齐目标和声音重建目标也应分开说明。

若与文本或动作融合，先对齐时间与任务坐标，再通过投影、交叉注意力、带模态标记的拼接或条件调制接入网络。隐藏维度相同不代表时间已经对应；音频驱动动作还要匹配音频帧率、动作帧率和窗口，文本通常提供更全局的约束。用去掉一个模态、打乱时间和错配文本的对照，验证模型真正使用了各类条件，而不是只走一条捷径。

#### 易错点

- 声学codec索引不是字符，也不天然只包含语义；低码率可能损失声学细节。

#### 追问

- 为什么低比特率 codec 可能损害细节理解？

<a id="omm-010"></a>
### OMM-010 · Qwen2-Audio 这类音频理解模型为什么不等于 ASR？

**L2**

#### 答案

ASR 主要回答“这段语音说了哪些文字”，音频理解还要回答“听到了什么、怎样说、声音意味着什么”。Qwen2-Audio 这类模型把音频编码器接到语言模型，可以用音频证据回答问题，但能力来自对应数据与训练，不是接上 LLM 就自动具备所有声音知识。

例如“有人在说快走”可以转写成文字；但背景有没有警报、说话是否愤怒、音乐是什么风格，仅靠这段转写可能看不出来。这些信息在声学特征里，先 ASR 再交给 LLM 的流水线可能把它们丢掉。直接音频输入更有机会保留，但仍需确认模型真正利用了声音。

评测应分开看语音内容、环境事件、音乐和声学属性，也区分用文字提问与直接语音指令的接口。同一句话配不同语气，或保留说话内容但替换背景声，是很有用的对照；去掉有关声音后答案应相应改变，才能说明回答依赖音频。

因此转写准确率是一个重要指标，却不是音频理解的全部表现或能力上限。还要评估噪声、模态缺失和不确定场景下是否乱猜，避免模型只靠问题文本的常识回答。

#### 易错点

- 不要把转写准确率当所有音频理解任务的上限。

#### 追问

- 同一句话不同语气如何构造评测？

### OMM-014 · 为什么唇读等视觉信息可以帮助噪声下的 ASR？

**L2**

#### 答案

唇读能帮助噪声下的语音识别，是因为嘴部动作与发音有关，相当于提供第二条证据。当环境很吵或某段音频缺失时，视觉线索可能帮助判断正在说什么。

AV-HuBERT 用音视频掩码和聚类目标学习联合表示，让模型利用声音与嘴部变化之间的对应。但口型并不能区分所有声音：有些不同发音看起来相似，视觉本身有歧义，所以它更适合作为补充，而不是完整替代可靠音频。

工程上先保证嘴部区域裁剪正确、说话人对应和音视频时钟同步。如果画面比声音晚一段时间，模型可能把不相关的口型当证据。侧脸、遮挡、多说话人和摄像头质量也会影响收益，因此要按这些条件及噪声强度分别评测。

我会比较纯音频、纯视觉与联合输入，并加入人为错位和遮挡对照，确定何时使用视觉、何时降低其权重或回退。触发降级的阈值应由真实设备和数据验证，不存在所有系统通用的“错位多少毫秒就一定失败”。

#### 易错点

- 相似口型可对应不同声音，唇读本身存在歧义。

<a id="omm-009"></a>
### OMM-009 · VALL-E 式零样本 TTS 为什么能利用短语音提示？

**L2**

#### 答案

VALL-E 把文字到语音建模成声学 codec token 的生成：文本告诉模型“说什么”，短参考语音告诉它“用什么说话人和声学风格说”。因此可以不给当前说话人单独微调，就合成类似其声音的语音，这就是这里的零样本 TTS。

参考语音先经 codec 编成离散声学提示，模型结合文字与提示预测后续声学 token，再由 codec 解码器还原波形。codec 的多个码本还原不同层次细节，原始 VALL-E 对首层和后续层采用不同生成安排，用自回归与非自回归部分配合，而不是直接逐个生成音频采样点。

这种能力来自训练中学到的文本、声学和说话人条件关系，不是复制一小段波形就能任意读新句子。参考太嘈杂、发音不清或语言超出训练覆盖，可能把噪声、风格和识别错误带到结果里。零样本也不证明训练集没有类似说话人或声学条件。

评测要分别看内容可懂度、说话人相似度、自然度、生成时延和噪声参考下的鲁棒性。只像原说话人却读错字，或内容正确但声音不稳定，都不能算完整成功；提示长度与 codec 层数还要按实际质量和预算权衡。

#### 易错点

- 零样本不表示训练集中不存在类似声学条件。

#### 追问

- 嘈杂提示会如何影响合成输出？

<a id="omm-012"></a>
### OMM-012 · ASR→LLM→TTS 流水线与端到端语音对话怎样选？

**L3**

#### 答案

我会按业务对可控性、声音表达和实时性的要求选择。ASR→LLM→TTS 把语音先转文字、再生成回答、最后合成声音，模块清晰，方便检查文本、接工具和替换组件；端到端语音模型则能直接利用更多声学信息，也更适合细致语气和多流对话。

流水线的缺点是转写可能丢失韵律或背景线索，识别错误会传给后面，模块衔接也增加等待。但它也能分块、并行和边生成边合成，因此端到端延迟不是三个整段耗时必然简单相加。客服业务若重视事实、审计与工具调用，可以从模块化系统起步，再定位关键路径。

端到端方案减少中间信息损失，却需要更复杂的训练数据、对话控制和评测。情感表达、同时听说的全双工场景可能更受益，但仍要检查说错内容、用户打断和恢复。端到端也可以保留文字接口与工具能力，不意味着必须舍弃这些控制通道。

我会在相同任务与设备下比较内容准确率、首音延迟、持续实时率、语气表达和打断恢复，再决定收益是否覆盖成本。架构标签不能替代完整系统实测，尤其要看用户实际听到声音的时间，而不只看模型输出第一个 token。

#### 易错点

- 端到端不等于必须舍弃文字接口或工具调用。

#### 追问

- 客服对话和情感陪伴的选择标准为何不同？

<a id="omm-013"></a>
### OMM-013 · 流式语音系统的端到端延迟应怎样拆解？

**L3**

#### 答案

流式语音的端到端延迟，要从用户输入到实际听见回答逐段拆，而不是只看模型推理耗时。它可能包括采集分块、编码器前视、识别或理解、回答生成、音频解码、网络传输和播放器缓冲。

其中“前视”是算法需要再等多少未来输入，比如要攒到一块音频才能判断；实际推理时间是算这块花了多久；网络和播放缓冲是传到客户端后还等多久。这三种等待性质不同，论文里 codec 的理论帧延迟只是其中一项，不能直接当用户端性能。

我会记录首个可播放音频包的延迟、长期生成相对音频时长的实时率，以及打断后多久真正静音。然后画出实际时间线，找哪些阶段可重叠、哪些必须等待；流式流水线优化应围绕关键路径，而不是机械相加每一段耗时。

块越小可能更快响应，却增加调度和网络开销，减少上下文后也可能损害音质与吞吐。降低声学 token 帧率减少模型负担，却可能让最小输出块更长。最后还需测长对话、并发、网络抖动和设备负载下的尾延迟，避免空载平均数掩盖真正卡顿。

#### 易错点

- 不能用论文理论延迟直接承诺用户端端到端延迟。

#### 追问

- 降低音频块大小为什么可能降低质量和吞吐？

<a id="omm-018"></a>
### OMM-018 · 实时视频通话 AI 如何主动响应、判断轮次并处理用户打断？

**L3** · 字节跳动

#### 答案

实时视频通话 AI 应把“持续感知”“什么时候开口”“说什么”分开处理。音视频按时间戳同步，维护用户当前任务、事件和已经说过的内容，只使用当前与过去输入。看到变化并不意味着必须立即评论，还要判断它是否相关、是否重复、用户是否正在讲话。

轮次判断不能只用固定静音时长。VAD 语音活动检测告诉我们有没有声音，语义与韵律帮助区分用户是在思考、附和还是把话轮交出来；视线可以辅助，但不能当确定命令。主动提示应围绕任务与偏好，设置冷却和去重，明确高优先提醒的策略。VideoLLM-online 的 Streaming EOS 表明响应时机可以训练，但并没有自动解决全部音频轮次问题；Moshi 等全双工模型也仍需控制何时保持沉默。

播放中继续监听，先处理扬声器回声，再识别真实 barge-in，即用户中途插话。用户说“停一下”时，应停止客户端播放、清空待播队列并取消过期生成；只取消推理而不清音频缓存，用户仍会听到后半段。历史只提交已经实际播出的内容及打断位置，用新问题重新规划；一句“嗯”可能只是附和，不应一律终止回答。

训练与评测需要沉默、重叠、停顿、主动触发和恢复样本。分别测触发精确率/召回、过早或过晚开口、误打断、插话到实际静音的延迟和恢复正确性。流式评测也不能提前看完整视频或未来转写来决定何时响应，答案质量和首包速度都不足以代表完整对话体验。

#### 易错点

- 全双工不意味着用户说话时必须始终输出语音，生成沉默也是有效行为。
- 取消推理请求、停止服务端TTS和停止客户端已缓存播放不是同一个操作。
- 流式评测不能提前读取完整视频或未来转写决定何时响应。

#### 追问

- 用户说“嗯”与“停一下”时，应怎样区分附和和打断？
- 网络抖动导致待播队列很长，怎样保证barge-in及时停止实际声音？

## Omni 融合与评测

<a id="omm-011"></a>
### OMM-011 · Qwen2.5-Omni 的 Thinker-Talker 如何协作？

**L2**

#### 答案

Qwen2.5-Omni 的 Thinker-Talker 可以理解为“先理解并形成回答，再把回答表达成声音”的协作结构，但两者通过模型表示连接，不只是先生成完整文本再调用一个独立 TTS。

Thinker 用音频和图像编码器读取多模态输入，再接入文本解码主干，输出文本与高层隐藏表示。Talker 同时利用这些连续表示和离散文本 token，既获取语义，也知道要怎样发音，再生成可流式解码的语音 token。这样声音表达可以随着文本生成推进，不必总等整段文字结束。

输入音频与视频还需要时间对齐。TMRoPE 等位置表达让同步的声音与画面处于可关联的时间位置，有助于理解“哪个声音对应哪个事件”，但位置对齐仍需正确时间戳和训练数据。不能把模型所有输入都说成离散 token：编码器的连续特征、文本 token 和声学 token 各有作用。

它支持联合训练，输出端仍要控制分块、音频解码感受野和首包延迟。评估除文本回答外，还应看语音内容一致性、发音、流式稳定性与音视频同步，不能因为叫 Omni 就假定任何模态组合都同样可靠。

#### 易错点

- 不要把 Omni 模型的全部输入或输出都说成离散 token。

- TMRoPE 对同步音视频输入有什么帮助？

<a id="omm-015"></a>
### OMM-015 · Omni 模型怎样评估是否真的融合了声音与视觉？

**L3**

#### 答案

证明 Omni 模型融合声音与视觉，需要题目本身必须同时依赖两种模态。若仅看画面就能答出“有一条狗”，同时输入声音并不能证明模型听到了什么。

例如问“视频里哪一个物体在发声”，画面告诉我们有哪些候选对象，声音与时间同步帮助判断谁发出声音。可以固定画面替换声音，或固定声音改变画面，再检查答案是否按证据变化。完整输入要与单模态基线比较；移除有关模态后，模型应降低把握或改变结论，而不是继续给同一答案。OmniBench 就强调视觉、声音与文字的联合识别和推理。

标注时还要记录答案依赖哪些模态和时间段，避免题目文字直接泄漏答案。同步、矛盾和缺失模态应分别测试：声音与画面矛盾时，要识别证据不足或解释矛盾，而不是强行融合成一个肯定答案。

最终同时看正确率、证据一致性、时序关系和不确定性处理。完整输入的总分高，也可能只是较强的单一模态走了捷径；只有在确需联合信息的对照中取得稳定收益，才有依据说发生了有效融合。

#### 易错点

- 多模态输入可被某个强模态捷径主导。

<a id="omm-016"></a>
### OMM-016 · ImageBind 如何用图像桥接多个模态，音频又如何编码？

**L2** · 腾讯

#### 答案

ImageBind 用图像作为共同桥梁，把多个模态放到同一个可比较的向量空间。图像/视频、文本、音频、深度、热成像和 IMU 各有编码器与投影头，并不共享同一个编码器，也不要求每个训练样本都同时包含六种模态。

训练利用自然配对，例如图文、视频与音频、图像与深度。对每种图像—模态配对做双向 InfoNCE，拉近同源表示、区分 batch 里的其他样本。公式中的 z 是归一化向量，I 表示图像、M 表示另一模态，τ_M 是温度、B 是配对数量；一个方向让图像选正确模态，另一方向反过来，两者相加。原始主要设置固定 OpenCLIP 的图像和文本编码器，训练音频、深度、热成像与 IMU 分支。

音频先转 Mel 频谱，再切时频 patch 交给 Transformer，最后池化、投影与归一化。原方案使用16 kHz的两秒音频、128个 Mel 频带，音频 patch16、stride10；这是时间和频率网格，不能按文字词位置理解。不同模态各自保留自己的输入结构，再通过训练建立共享表示。

因为音频和文本都靠近图像空间，可能出现未经直接音频—文本配对训练的检索能力。这是实验观察，不保证任意模态都精确对齐。画外声音、错配视频和假负例仍会损害效果。ImageBind 主要输出表示，若要生成回答或声音，还要接语言模型或相应解码器。

```math
\begin{aligned} \ell_{I\to M}&=-\frac{1}{B}\sum_{i=1}^{B}\log\frac{\exp(z_i^{I\top}z_i^M/\tau_M)}{\sum_{j=1}^{B}\exp(z_i^{I\top}z_j^M/\tau_M)}\\ \mathcal L&=\sum_M\left(\ell_{I\to M}+\ell_{M\to I}\right),\qquad \|z_i^M\|_2=1 \end{aligned}
```

#### 易错点

- 不需六模态同时出现，不表示没有配对监督。
- 共享向量空间不等于共享编码器，也不自动具备文字或音频生成能力。

- 同一视频中的声音来自画外时，怎样过滤配对噪声？
- 如何设计去除图像桥梁或加入直接音频文本配对的消融？
