<a id="pre-001"></a>
### PRE-001 · 自回归预训练的 next-token loss 怎样计算？

**L1** · 阿里巴巴

#### 答案

自回归预训练就是让模型看着前面的文字猜下一个 token，猜得越准，训练损失越小。Token 是分词器切出的文字单位，不一定对应一个汉字或单词。公式中的 $`x_t`$ 是第 $`t`$ 个 token，$`x_{<t}`$ 是它之前的内容，$`\theta`$ 是模型参数；整段文本的概率等于每一步条件概率的乘积，这表达的是前后依赖，并不是每个 token 相互独立。

训练时我们已经知道整段真实文本，所以可以把各位置一起送进模型，用因果注意力遮住未来，再一次算出所有位置的预测。这个做法叫 teacher forcing，也就是始终用真实历史作为条件。例如输入“我、爱、学习”，第一位置预测“爱”，第二位置预测“学习”。假如正确 token 的概率是 0.8，该位置损失就是 $`-\log 0.8`$，约 0.223；概率只有 0.1，损失就约 2.303。把所有有效目标的损失相加，再除以有效目标数，就是常用的 next-token loss。

实现里最容易错的是标签对齐和计损范围。模型若已在内部把预测与后一个标签对齐，数据处理就不能再移动一次。填充位置和不应跨越的样本边界要忽略；是否监督开头、结束符，也要按配方明确。有提示词时，可以不计算提示词本身的损失，但回答仍需要读到它。训练能并行计算，是因为真实历史已知；生成时历史由刚生成的 token 决定，通常仍要逐步解码，缓存历史键和值只是在减少重复计算。

```math
\begin{aligned}p_\theta(x_{1:T})&=\prod_{t=1}^T p_\theta(x_t\mid x_{\lt t})\\\mathcal L&=-\frac1{N_{\rm valid}}\sum_{t\in\mathcal T_{\rm valid}}\log p_\theta(x_t\mid x_{\lt t})\end{aligned}
```

#### 易错点

- 输入与标签只对齐移动一次，重复 shift 会让预测目标错一位。
- 提示词不计损不等于不可读取，训练并行也不等于生成 token 相互独立。

<a id="pre-004"></a>
### PRE-004 · Scaling Law 描述的是什么，能直接预测下游能力吗？

**L2** · 阿里巴巴

#### 答案

Scaling Law 是用实验规律估计“多投入一些模型参数、数据或计算量，损失能下降多少”，主要用来分配训练预算。它通常拟合的是没参与训练的文本上的预测损失，而不是直接承诺某个下游任务的准确率。参数量 $`N`$ 表示模型大小，$`D`$ 表示训练 token 数，$`C`$ 表示计算量；在一定实验范围内，损失对这些资源常呈近似幂律变化。

实际使用时，会训练几种规模的模型和几种训练长度，拟合资源与损失的关系，再用没有参与拟合的规模验证外推。例如预算固定时，比较“模型扩大两倍、数据减半”与“模型保持较小、多读一些数据”，找出验证损失更低的配置。只看曲线贴合得好还不够：数据质量、重复次数、架构和学习率调度一变，拟合系数也可能变化。

下游能力还受提示词、任务指标和后训练影响。同样下降的语言建模损失，可能对翻译帮助很大，对某个严格判分的推理任务帮助很小，所以能力需要单独评测。还可以研究推理时增加思考 token、候选采样、搜索或工具调用的收益，但这要重新测质量和延迟曲线。一次生成十个候选，其中有一个正确，只说明候选集合的上限提高；实际系统能否选中它还取决于验证器。最终预算也应包括长期推理成本，训练最省算力的模型未必是部署最划算的模型。

#### 易错点

- 把有限实验范围内的经验曲线当成任意规模都成立的定理。
- 把语言建模损失的下降直接当作准确率或安全性提升。

#### 追问

### PRE-005 · Chinchilla 的结论是什么，tokens≈20×参数是硬规则吗？

**L2**

#### 答案

Chinchilla 的核心结论是：训练预算一定时，不能只追求更大的模型，还要给它足够的数据；在论文的实验范围里，参数量和训练 token 数应大致同步增长。常说的“每个参数训练约 20 个 token”，是这个实验拟合出的量级参考，不是超过或低于它就一定好坏的硬规则。

公式 $`C\approx6ND`$ 是稠密 Transformer 训练计算量的粗略估算，$`N`$ 是参数量，$`D`$ 是见过的 token 数，$`C`$ 是浮点运算次数。比如同一预算下把参数量翻倍，按这个近似就只能训练原来一半的 token；更大模型若没训练充分，可能输给更小模型。寻找最优点的方法，是固定总计算量，扫描不同模型大小，并为每种大小安排相应的数据量和完整学习率调度，再比较最终验证损失。

这个结论依赖数据质量、架构和实验预算。长上下文中的注意力计算要额外考虑，稀疏专家模型也不能直接拿总参数代入稠密公式。若模型上线后会被调用很多次，较小模型训练更久，虽然一次训练偏离“计算最优”点，却可能靠更便宜的推理降低总成本。因此我会把 20 倍当作起始估计，再结合独立数据量、任务质量和服务成本做选择。

```math
C\approx6ND
```

#### 易错点

- 把 20 tokens/parameter 当成达到能力上限的通用阈值。
- 直接将 dense 估算套到总参数很大的稀疏 MoE。

#### 追问

- 70B 与 7B 在相同训练预算下怎样比较？
- 什么时候会选择过度训练较小模型？

<a id="pre-015"></a>
### PRE-015 · perplexity 怎样计算才可公平比较？

**L1**

#### 答案

困惑度 PPL 是“模型平均有多难猜中真实下一个 token”的一种指标，越低说明在指定文本上的预测越好，但不直接等于对话或推理质量。它把有效 token 的平均负对数概率取指数。公式里的 NLL 是负对数似然，$`N_{\rm valid}`$ 是参与计分的目标数；若平均 NLL 是 1，PPL 就是 $`e`$，约 2.72。

公平比较必须使用相同语料、分词器、上下文长度和计分范围。不同分词器可能把同一句话切成完全不同数量的 token，token 级 PPL 就不能直接排名，可以另用每字节的比特数等统一单位。多个 batch 的结果也应先按有效 token 汇总 NLL，再取指数，而不是把各 batch 的 PPL 等权平均。提示词、填充和回答是否计分要保持一致。

长文超过模型窗口时，互不重叠切块会让每块开头丢失历史，通常使 PPL 偏高。滑动窗口能为新目标补足上下文，但重叠部分应只提供条件，不重复计分；还要处理内部 label shift 后实际有效的目标数。滑动步长变小所得分数可能改善，是因为提供了更多上下文，不能误认为模型参数变强了。评估时最好把 PPL 与事实性、指令遵循和任务正确率一起看。

```math
\mathrm{PPL}=\exp\!\left(\frac{\sum_{t\in\mathcal T_{\rm valid}}\mathrm{NLL}_t}{N_{\rm valid}}\right)
```

#### 易错点

- 先算各 batch PPL 再等权平均。
- 对 prompt、padding 和目标回答采用不一致的计损策略。

#### 追问

- 为什么更短的评测 stride 可能得到更低 PPL？
- 如何处理超长语料的首个 token？

### PRE-016 · 预训练语料有限时能否重复多 epoch，如何识别收益递减与过拟合？

**L2**

#### 答案

预训练数据有限时可以重复多轮，模型仍可能学到有用结构，但重复 token 不等于同样数量的新信息，越往后通常越需要警惕收益递减和记忆。一个 epoch 表示把规定的数据大致看过一遍；公式中的 $`D_{\rm unique}`$ 是独特 token 数，$`E`$ 是曝光轮数，$`D_{\rm seen}=E D_{\rm unique}`$ 只统计总阅读量，不保证有效信息也增加 $`E`$ 倍。

比如只有一百亿高质量 token，训练三轮会看到三百亿 token，但内容仍只有一百亿独特 token。早期重复可能让之前没学充分的模式更稳定，继续重复却可能主要记住措辞。判断时要看独立验证损失、训练验证差距、真实下游任务，以及逐字复现或成员推断等记忆信号。还可以固定总计算量，比较“较大模型少读几轮”和“较小模型多读几轮”，不能只比较训练 loss。

去掉网页意外副本与有计划地重复高质量领域数据并不矛盾：前者让曝光可控，后者是在明确分配预算。实践中可扩充同质量而更丰富的数据、混入通用回放、适当正则，并记录不同来源的曝光次数。某些研究中少量重复接近新增数据的收益，只能说明对应设置的现象，不能给所有大模型规定一个通用 epoch 上限，也不能保证继续加轮数一定获得新能力。

```math
D_{\rm seen}=E\,D_{\rm unique},\qquad D_{\rm effective}\ne D_{\rm seen}\ \text{in general}
```

#### 易错点

- 把重复token的数量当作同等数量的新信息。
- 断言第2个epoch以后所有大模型都会变差。

#### 追问

- 去重和有意上采样为什么并不矛盾？
- 如何固定FLOPs比较增模型与重复数据？

### PRE-017 · 大模型的“涌现能力”怎样定义，指标突变是否证明机制相变？

**L3**

#### 答案

大模型的涌现能力，通常指某项能力在小模型上几乎看不到，规模增大后明显出现，而且难从小规模结果外推；一条评测曲线突然上升，并不能单独证明模型内部发生了机制相变。评测规则本身就可能把平滑的能力提升变成跳变。

例如一道题要求十步都对才给分，假设各步独立且单步正确率是 $`p`$，整题正确率就是 $`p^{10}`$。这里独立只是一种解释指标的玩具假设，真实推理步骤未必独立。即使单步能力逐渐改善，“全对才算”的严格指标也可能在某个区间看起来突然跨过门槛。精确字符串匹配还有类似问题：答案已经接近正确但格式差一点，仍然被记为零分。

要判断现象，需要增加规模采样点，同时报告部分正确、连续分数、预测概率或校准表现，并控制训练数据、预算、提示词和评测样本。指标效应能够解释部分跳变，并不证明所有新能力都是幻觉。若要主张内部算法发生质变，还需要可重复的干预、表示分析或计算过程证据。Grokking 是沿训练时间出现的延迟泛化，和跨模型规模的涌现不是同一个定义。实际选型时，我会先验证目标任务是否稳定变好，以及资源代价是否值得。

```math
P(\text{all }m\text{ steps correct})=p^m\quad\text{under an independence toy assumption}
```

#### 易错点

- 严格全对指标跳变，不足以证明内部算法突然变化。
- 沿训练时间的 grokking、跨规模涌现和创造性生成不是同一个概念。

#### 追问

- 换成部分正确评分为何可能使能力曲线更平滑？
- 如何验证观察不是prompt或数据混杂造成的？

<a id="pre-018"></a>
### PRE-018 · Fill-in-the-Middle 预训练怎样让 causal LM 根据前后文补全代码？

**L2**

#### 答案

Fill-in-the-Middle，简称 FIM，是把前文和后文都放到待补内容之前，让原本只向前看的语言模型也能学会中间补全。它改变的是训练文本排列，而不一定需要改成双向注意力。代码编辑中很自然的场景，就是函数上半段和下半段都已存在，模型只填中间几行。

训练时把文档切成前缀 $`P`$、中间 $`M`$、后缀 $`S`$，用专门标记组成“前缀标记、前文、后缀标记、后文、中间标记、待补内容”的序列，这叫 PSM 排列。也可以混合其他排列。生成中间内容时，后文虽然在原文件里靠后，却已经出现在模型当前的输入历史里，所以正常因果 mask 就够了。公式中的 $`M_t`$ 是中间部分第 $`t`$ 个 token，模型在前后文与已生成的 $`M_{<t}`$ 条件下逐步预测它。

数据切点要合法，并控制 FIM 与普通左到右文本的混合比例。对代码还要检查缩进、语法和分词边界，分别评估普通续写与中间补全，普通困惑度不能完整验收。某个模型是否支持 FIM，要核对具体检查点和标记协议，不能对没有学过这些标记的模型直接拼上字符串就假定具备能力。它也不同于 BERT 在原文位置预测遮住的词：FIM 仍然是在变换后的序列里逐 token 生成。

```math
p(M\mid P,S)=\prod_{t=1}^{|M|}p(M_t\mid\mathrm{format}(P,S),M_{\lt t})
```

#### 易错点

- 认为causal LM永远无法使用后缀文本作为条件。
- 对未学过FIM标记的模型直接拼标记并假设已获得infill能力。

#### 追问

- 切点在token化之前还是之后有什么差别？
- 如何验证FIM训练没有破坏普通左到右续写？

<a id="pre-006"></a>
### PRE-006 · 大规模预训练语料应怎样清洗？

**L2** · 阿里巴巴

#### 答案

预训练语料清洗的目的，是让模型读到可靠、丰富、符合目标场景的文字，而不是单纯把数据变少或让处理速度变快。通常先提取正文、识别语言，再过滤明显垃圾、去重、排除评测泄漏和敏感信息，最后检查各类数据还剩多少。网页里的导航、广告和乱码需要清理，但代码、数学公式和少数语言不能直接套普通文章的规则。

我会把简单规则和模型评分结合使用，并按来源、语言、领域和分数分层抽查。例如某个过滤器删掉了八成数学文本，不能看到总体平均分提高就接受，要确认它是否把公式符号误判为乱码。去重后也要重新计算唯一 token 和采样权重，避免“同一篇文章的十个镜像站”实际占了十份训练预算。每一步保留样本来源、规则版本和删留理由，出现异常时才能追查。

验收不能只看清洗后的训练损失。应固定留出集，用小模型对比过滤前后的领域覆盖、任务效果和记忆风险。若还用模型生成标签，要用独立规则、执行器或人工检查，不能让同一个教师既出答案又作为唯一裁判。多模态数据还要核验图文是否匹配、坐标和时间戳是否正确，并检查 OCR、公式提取和视觉描述是否忠于原始可见内容，避免生成标签凭空补出图中没有的信息。划分训练测试集时，尽量先按实体和近重复簇隔离，防止同一内容的改写或派生样本进入两边。清洗越严格越可能牺牲长尾覆盖，所以需要同时看可靠性和多样性。

#### 易错点

- 高困惑度可能来自专业或稀有内容，不能一律当垃圾。
- 只看总保留率，不检查少数语言和专业领域被误删的比例。

#### 追问

- 如何量化清洗造成的分布偏移？
- 为什么代码或数学文本需要单独制定过滤规则？

<a id="pre-007"></a>
### PRE-007 · 精确去重与近似去重有哪些方法和边界？

**L2**

#### 答案

精确去重找的是完全相同的内容，近似去重找的是改了一点但基本相同的副本，目的都是避免模型把重复材料当作大量独立信息。精确去重可以对规范化后的文档算哈希：去掉无关空白等差异后，哈希相同就形成重复候选。它便宜，但文章换了标题、插了一段广告，就可能查不出来。

近似去重通常先把文本拆成连续的词或字符片段，这些片段叫 shingles，再用 MinHash 等方法快速估计集合重合度，筛出候选后进一步比较。例如一篇文章有一百个片段，镜像版只有十个片段不同，就很可能被归入同一簇。大规模语料不宜所有文档两两比较，可以通过分桶和近邻候选降低成本。对于网页公共导航、免责声明，还可以在段落或长子串层面去重。

找到重复簇后，最好根据正文完整度和来源质量选代表，而不是随机留下一个残缺副本，并保存删留映射。阈值要通过人工抽样评估误删和漏删：相同模板下的不同事实问答，虽然表达相近，却不应全部删除。去重能减少重复曝光、逐字记忆和训练测试重叠，但不能消灭翻译改写或语义泄漏。去重之后训练损失有时反而升高，因为容易记住的副本少了；这不直接说明数据质量变差，还要看独立验证和真实任务。

#### 易错点

- 网址不同不代表内容独立，镜像和转载仍可能重复。
- 语义相近但事实不同的样本不应被一律删掉。

#### 追问

- 如何在大规模语料上控制近似去重成本？
- 为什么 dedup 之后验证 loss 可能上升但可信度提高？

<a id="pre-008"></a>
### PRE-008 · 怎样检测与减少 benchmark contamination？

**L2**

#### 答案

评测污染是指模型训练时见过测试题、答案或高度相似的题解，导致高分可能来自记忆，不能可靠代表对新问题的泛化。检测时要查题干，也要查答案和解析；仅删除测试集原网址或完全相同的一行文字，通常不够。

具体可以建立测试内容清单，用文档哈希、连续片段重叠和近似检索找候选，再人工检查镜像网页、翻译和改写。例如数学测试题换了人名但沿用了数值和解题过程，字面匹配可能漏掉；另一方面，教材里介绍同一个公式，并不一定意味着泄漏了这道具体测试题。检测标准应区分一般领域知识与完整试题暴露，并记录误报边界。

减少污染要尽早做数据隔离，可以按来源、时间、实体或任务组切分，并在训练前排除已知评测内容。评测时同时报告可检测的污染比例、清洁子集成绩，以及新编受控题上的表现。对于无法审计训练数据的闭源模型，可以补充最新题、私有题和可验证的任务，但这些也只能增加证据。没搜到重叠不能证明完全没污染，高分本身也不能证明一定泄漏；最终结论要和检测方法的覆盖范围一起解释。

#### 易错点

- 把预训练见过某领域事实与见过完整测试题一概混称同一污染。
- 根据高分反推模型必然泄漏。

#### 追问

- 闭源模型无法审计训练集时怎么补充评估？
- 污染检测为什么需要保留误报边界？

<a id="pre-009"></a>
### PRE-009 · 代码、网页、多语言等预训练数据如何配比？

**L2**

#### 答案

预训练数据配比，就是决定模型把多少训练预算花在网页、代码、多语言等不同内容上，目标是服务需要的能力，而不是按文件数量平均分。首先统一统计口径：一份长代码文件和一句短文本不能各算一个同等样本，应该同时记录有效 token、独特 token 和重复曝光次数。

我会先设一个覆盖主要领域的配比，再用较小的代理模型做实验，分别看各领域验证损失和下游任务。例如代码比例提高后，代码补全可能变好，但中文对话或其他语言可能因预算被挤占而退化；这需要联合观察。DoReMi 一类方法会让代理模型学习不同领域的权重，之后用这些权重训练目标模型，但代理模型的结论仍要验证能否迁移。

配比实验最好固定总训练 token 或计算量，保持其他设置一致，并让主要领域各有独立验证集。高损失领域不一定应该加更多权重：它可能确实没学好，也可能充满噪声或本来就更难预测。稀缺的高质量领域数据可以适度重复采样，但要检查记忆和收益递减。配比回答“学什么、学多少”，课程学习还回答“按什么顺序学”，两者可以结合，但都不存在脱离数据和目标的通用最优比例。

#### 易错点

- 高 loss 的领域永远应该加权更多，忽略噪声或任务难度。
- 把论文给出的配比直接用在不同数据和目标上。

#### 追问

- 如何设计配比 ablation 避免算力不公平？
- 数据配比与课程学习有什么区别？

## 训练精度与优化

<a id="pre-012"></a>
### PRE-012 · AdamW 与 Adam 加 L2 正则为什么不等价？

**L2**

#### 答案

AdamW 把权重衰减从损失梯度里拆出来，直接让参数略微缩小；Adam 加 L2 正则则把参数大小的惩罚先加入梯度，两者在自适应优化里通常不等价。区别来自 Adam 会根据历史梯度的一阶、二阶统计，对不同参数的更新进行不同缩放。

假设损失加上 $`\lambda\lVert\theta\rVert^2/2`$，梯度就多了 $`\lambda\theta`$。在普通 Adam 里，这一项和任务梯度一起进入动量及二阶矩，衰减效果也跟着每个参数的历史缩放变化。AdamW 让动量和二阶矩只跟踪任务梯度，另按更新前参数施加衰减：新参数等于 $`(1-\eta\lambda)`$ 倍旧参数，再减去 Adam 的任务更新；$`\eta`$ 是学习率，$`\lambda`$ 是衰减系数。比如暂时忽略任务梯度，参数是 10、学习率 0.001、衰减系数 0.1，这一步直接衰减约 0.001。

因此，两个优化器即使都提供叫 weight_decay 的参数，也要看它实现的是哪种规则。普通 SGD 在合适系数约定下的等价关系，不能直接搬到 Adam。比较配置时还要匹配学习率调度和更新次数，因为长期累计衰减会不同。哪些参数组要衰减，例如偏置、归一化或 LoRA 参数，要按训练配方验证，不能认为所有模型都必须使用同一套排除规则。

#### 易错点

- 说 AdamW 只是 Adam 的别名。
- 无依据断言所有 embedding、norm 必须采用同一种衰减配置。

#### 追问

- 为什么相同 `weight_decay` 在不同训练时长下效果不同？
- LoRA 参数是否应该使用权重衰减？

<a id="pre-013"></a>
### PRE-013 · FP16 与 BF16 的差异是什么，混合精度为何有用？

**L1**

#### 答案

FP16 和 BF16 都用 16 位存一个数，前者把更多位数用于细分数值，后者把更多位数用于表示数值范围；混合精度就是让适合的计算用低精度，同时让敏感部分保留较高精度，以节省显存并提高速度。FP16 的符号、指数、尾数分别占 1、5、10 位，BF16 分别占 1、8、7 位。

可以把指数理解成数字的数量级，尾数理解成该数量级内的刻度。BF16 的指数范围接近 FP32，较大或较小的值更不容易溢出、下溢；FP16 在相近量级下刻度更细，但最大有限值约为 65504，大激活可能超出范围。FP16 训练常把损失先放大，使很小的梯度落入可表示范围，反向后再缩回，这叫 loss scaling。BF16 通常不需要这一步，但舍入误差和非有限数仍可能出现。

自动混合精度会按算子选择计算类型，并不是简单把整个模型和所有张量都转成 half。归一化、softmax、损失归约或优化器状态可能使用 FP32，具体取决于框架和内核。若使用缩放梯度，梯度裁剪应在恢复原始尺度之后进行。Loss scaling 能缓解梯度下溢，却不能修复前向已经产生的溢出。最终速度和稳定性要在目标硬件上检查，包括 NaN、Inf、梯度范数和任务效果，不能只按位数判断谁更准确或更快。

#### 易错点

- BF16 精度在所有数值范围都高于 FP16。
- loss scaling 能修复前向激活溢出。

#### 追问

- 为什么部分 norm 或 softmax 使用 FP32？
- FP16 的梯度裁剪前应做什么？

<a id="pre-014"></a>
### PRE-014 · warmup、学习率衰减和梯度裁剪各解决什么问题？

**L2**

#### 答案

Warmup、学习率衰减和梯度裁剪分别是在训练开头、训练后期和异常大梯度出现时控制更新幅度，三者解决的问题不同。Warmup 从较小学习率逐步升高，让优化器统计和模型内部尺度有时间建立；衰减则在后期减小更新，帮助细化已有解；裁剪限制当前梯度过大造成的冲击。

原 Transformer 的 Noam 调度先线性升高，再按更新步数的平方根倒数下降。公式里的 $`s\ge1`$ 是真正的参数更新步，$`D`$ 是模型维度，$`w`$ 是 warmup 步数，$`c`$ 是整体系数。交点 $`s=w`$ 时学习率达到 $`c/\sqrt{Dw}`$；若其他量不变，warmup 步数扩大四倍，峰值会减半。原实验使用 4000 步只是历史配方，现代训练也常用线性或余弦衰减，warmup 长短要结合规模和初始化选择。

全局范数裁剪把所有参数的梯度看成一个大向量。$`g_p`$ 是参数 $`p`$ 的梯度，$`G`$ 是整体二范数，$`C`$ 是阈值；若 $`G=10`$、$`C=1`$，就把所有梯度统一乘 0.1，保持方向。它不同于逐元素截断，也不同于每个张量分别裁剪。应先完成梯度累积、恢复混合精度的缩放，再裁剪并更新；调度器按实际更新计步，分片训练还要正确汇总全局范数。

裁剪无法修复 NaN 或 Inf，也不保证 Adam 的实际参数更新范数小于学习率乘阈值，因为动量、二阶矩和衰减还会参与更新。如果长期大量触发裁剪，应检查原始梯度范数、数据、学习率和数值精度，不能只把阈值调小掩盖问题。

```math
\begin{aligned}\eta(s)&=cD^{-1/2}\min(s^{-1/2},sw^{-3/2}),\quad s\ge1\\G&=\sqrt{\sum_p\|g_p\|_2^2}\\g'_p&=\begin{cases}g_p\min(1,C/G),&G\gt 0\\0,&G=0\end{cases}\end{aligned}
```

#### 易错点

- 在混合精度解除缩放前按原阈值裁剪，或把逐张量裁剪称为全局范数裁剪。
- Noam 的历史 warmup 步数不是通用配置，步数从零代入负幂也不合法。

#### 追问

- 其他参数不变，Noam 的 warmup 步数扩大四倍，峰值学习率怎样变化？
- 为什么裁剪了梯度范数，Adam 的实际参数更新仍不一定小于学习率乘阈值？

## 继续预训练与域适配

<a id="pre-011"></a>
### PRE-011 · 继续预训练与 SFT 的数据和目标有什么区别？

**L1** · 字节跳动 / 腾讯

#### 答案

继续预训练是让模型继续阅读领域文本，适应领域语言和知识；SFT 是用明确的输入输出例子，教模型按任务要求回答。两者都可能采用下一个 token 的交叉熵，区别主要在数据组织和希望学到的行为，而不是一个必须全参数、另一个必须 LoRA。

例如做法律助手，继续预训练可以使用法规和判决正文，让模型熟悉术语、表达和关联；SFT 则给“用户问题—符合要求的解释”或结构化抽取例子，教会答案格式、引用方式和适当边界。领域原始数据多、与通用文本差异大时，可考虑先做领域继续预训练，再做指令 SFT；若任务主要是固定格式输出，也可以先用 SFT 验证是否已经足够。

两者都要分别检查领域收益和通用能力回归。领域损失下降不代表模型就会遵循指令，SFT 也不是只换说话风格，它可能改变或学习内容知识。知识更新很频繁、需要实时依据或权限控制时，检索增强生成往往更便于维护，但它也需要可靠的检索和证据使用能力。选择训练目标和选择参数更新方式是两件事：继续预训练也能用参数高效方法，SFT 也能更新全部权重。

#### 易错点

- 把继续预训练简单定义为全参数微调，SFT 简单定义为 LoRA。
- 认为任何新增知识都必须继续预训练。

#### 追问

- 领域知识变化很快时为什么还会考虑 RAG？
- CPT 之后 SFT 数据如何补足交互格式？
