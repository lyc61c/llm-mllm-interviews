## 评测协议与基准

<a id="eva-001"></a>
### EVA-001 · 如何避免训练数据污染评测集？

**L2** · 字节跳动

#### 答案

评测污染是测试内容或答案进入训练、合成数据或调参流程，导致分数反映记忆而不是泛化。除了原题重复，翻译、近似改写、同一答案段落和模板也可能泄漏。我会按文档来源、实体、用户或时间分组划分，再结合精确与语义去重，而不是只随机拆行或检查 n-gram。

例如同一用户的问题有多种问法，应放在同一分组，不能训练一种问法、测试另一种。合成数据也要追踪源问题、生成提示和教师输出，避免把公开评测题间接带入训练。开发集用于选方案，最终验收集保留到最后，反复看测试分数调参数同样会造成乐观偏差。

我会保留版本化的新鲜私有测试，报告类别覆盖与重复检查方法。分组拆分后类别不均衡，可以在组内分层采样、补新组或报告各类指标，不能为平衡把同一来源拆回两边。训练语料未知时，未检出重叠不证明没有污染；仅改几个词也不能把公开题称为全新基准。

#### 易错点

- 检测不到重叠不等于证明无污染；不能只改几个词就称新基准。

#### 追问

- 项目数据量小，按用户拆分后类别不平衡怎么处理？

<a id="eva-011"></a>
### EVA-011 · MLLM 评测如何区分感知、OCR 与推理错误？

**L2**

#### 答案

多模态大模型答错，可能是没看清文字、没定位对象、看错图表，也可能是跨模态关系或后续推理出错。我会按 OCR、计数、空间关系、图表和专业推理拆分样本，固定图片数、分辨率、输入预处理和答案解析，避免用一个综合分覆盖全部能力。

定位根因可以对照原图、局部裁剪、人工文字转写和纯文本输入。例如原图错误、人工 OCR 正确，提示感知或读字存在瓶颈；裁剪后正确，则可能是分辨率或注意力定位问题。替换或打乱图片后答案不变，也可能表示模型依赖语言先验，但要排除问题本来就无需图像或有多个有效答案。

我会让这些消融只改变一个因素，并检查人工转写是否额外提供了原图没有的解释。视觉问答高分不能直接推断视频时序、定位或高分辨率小字都好。改进后还要回归对应子能力和域外样本，确认修好了感知，而不是仅改变了解答格式。

#### 易错点

- 一个综合榜单不能代表视频、定位或高分辨率读图的全部能力。

#### 追问

- 原图错、人工 OCR 文本对时，应优先改哪一环？

<a id="eva-013"></a>
### EVA-013 · 如何验证 prompt 优化确实有效？

**L2** · 字节跳动

#### 答案

Prompt 优化要做成受控实验：先定义要改善的可观察目标，固定模型、解码和预算，每次改变一个明确因素，在留出样本上比较。一个演示变好只能说明那道题，不能证明泛化。模板与少样本示例要版本化，并检查示例和测试内容是否重叠。

格式目标可以直接检测，例如 JSON、字段、长度或关键词；事实与语义要用证据、执行或人工评价。多条指令既要统计各条满足率，也要统计全部满足的整题通过率，不能每条看着都高却忽略共同失败。例如输出有正确字段但内容错误，格式成功和任务成功必须分开。

我会观察不同难度和领域的变化，开发集涨、留出集跌时优先查过拟合、示例偏置和约束冲突。增加要求可能互相矛盾，低温也不必然让答案更短。最终保留在独立集上有稳定收益、成本可接受的修改，而不是不断堆提示语直到训练样本全对。

#### 易错点

- 更多提示要求可能冲突，降低温度也不保证输出更短。

#### 追问

- 同一提示在开发样本上提高、留出集却下降，应该怎样处理？

<a id="eva-015"></a>
### EVA-015 · 线上如何监控、验收并回归 LLM/Agent 系统？

**L2**

#### 答案

线上验收不止看离线分数，还要观察任务成功、拒答、工具错误、事实反馈、延迟与成本。我会保存模型、提示、索引和工具版本，以及能重放的请求、检索、行动和结果 trace，对敏感字段做最小化记录和访问控制。

例如上线后成本突然升高，先把 token、重试、检索和工具次数拆开，定位是更长回答、循环还是缓存变化；点击率提高也可能来自曝光或界面变化，不能直接当答案更正确。按风险与流量分层抽检，把新失败加入回归，同时保留独立验收集，避免只围绕已知 bad case 调整。

发布前后要同口径比较质量、边界与效率，随机任务重复运行，限流、断线与恢复做故障注入。提前设退化和回滚条件，尤其检查重要分组，平均分变好不能抵消新增越权或严重事实错误。最终用真实结果和受控对照解释变化，而不是仅凭用户互动量判断模型能力。

#### 易错点

- 把线上点击率当答案正确率会受曝光、用户群与界面变化混杂。

#### 追问

- 线上成本骤增但准确率没变，应怎样定位？

<a id="eva-016"></a>
### EVA-016 · MMLU、BIG-bench/BBH、GSM8K 与 HumanEval 分别测什么，怎样读榜单？

**L2**

#### 答案

不同基准测的是不同任务。MMLU 是 57 个学科的选择题，偏知识和问题解决；BIG-bench 覆盖很多任务，BBH 是其中较难的一组，二者不能混成一个分数。GSM8K 主要是数学应用题，要按协议提取最终答案；HumanEval 用函数题和测试看代码功能，pass@k 还依赖采样与解码。

读榜单时我会检查模型版本、数据划分、提示、示例、选项顺序、答案解析和计算预算。选择题可以按选项似然评分，也可以让模型直接生成选项，两种协议会测到不同表现；更多思考 token 或更多候选带来的提升，也不能全部归给参数规模。污染和题目重复同样需要核查。

例如选项似然高，但生成回答常不遵守格式，说明知识选择与指令执行要分别评价。综合平均会遮住短板，这些分数也不能证明长上下文、拒答、工具或多语言能力。我会用公开基准筛候选，再用独立业务集和分层错误分析决定是否满足需求。

#### 易错点

- 同名基准可能使用不同示例、推理提示、答案解析与采样预算，榜单不能直接混比。

#### 追问

- 按选项概率评分很高，却不能稳定生成合规格式，怎样分别评价两种能力？

<a id="eva-017"></a>
### EVA-017 · AgentBench、WebArena、GAIA、SWE-bench 与 τ-bench 怎样评价 Agent？

**L2**

#### 答案

Agent 基准重点是交互后有没有达到目标。AgentBench 覆盖多种决策环境，WebArena 看网页任务的状态达成，GAIA 常需要检索、文件、多模态和工具组合，SWE-bench 看真实仓库问题修复及测试，τ-bench 看工具、模拟用户和领域政策的交互。它们的任务范围与验收方式不同，不能合成一个万能 Agent 分数。

我会固定初始状态、权限、工具与依赖版本、网络条件和预算，区分环境状态验收、最终答案匹配与代码测试。动态网页和模拟用户可能有随机性，不能把所有基准说成完全离线、绝对确定；环境故障也要单列，参考解可用于检查评测链路。

多次运行后报告成功率与不确定度、调用成本、延迟、越权和恢复。一次成功可能来自幸运采样，代码测试通过也可能覆盖不到完整业务。真实产品要选择与自身动作空间和失败代价一致的任务，问答正确率不能替代网页或代码 Agent 的实际执行验收。

#### 易错点

- 文档检索问答基准的答案正确率不能替代网页/代码Agent的环境状态验收。

#### 追问

- 同一Agent多次运行时成功率差异大，怎样设计重复试验和置信区间？

<a id="eva-018"></a>
### EVA-018 · 怎样设计可靠的 benchmark，并用评测框架建立可复现验收？

**L2** · 腾讯

#### 答案

可靠 benchmark 首先定义目标能力、适用场景、任务和评分，而框架负责把协议执行起来。LM Evaluation Harness 将任务与模型后端分离，便于固定少样本、似然或生成评分及答案过滤；RAG 还要验证证据，Agent 还要检查轨迹和环境，不能只套文本匹配。

我会固定数据、模型、tokenizer、模板、解码预算与停止规则，保存原始输出和评分中间结果，写清分母、失败超时处理及任务权重。训练、开发与验收集分开，控制重复、模板捷径和语言先验，多模态用遮图、换图或人工转写检查是否真的依赖视觉。样本要覆盖真实任务和难例，标签可复核，分数分组报告并给置信区间。

新增模型或提示先小批量确认输入和解析，再跑冻结回归；随机任务重跑，评分器抽查人工一致性。RAG 保存证据版本，Agent 重置初态并检查副作用。框架升级导致分数变化时，先对照相同样本的原输入、输出和解析，不直接说能力改变。

脚本跑完不代表协议一致，错误解析可能造出零分或高分。还要识别标注歧义、基准饱和和成本变化，保留新领域独立测试，避免反复调过的题仍被当成最终验收。最后按业务质量、延迟和成本阈值判断是否可用，而不是只存一个平均分。

#### 易错点

- 评测脚本运行成功不代表协议一致，模型输出解析错误可造成虚假零分或高分。

#### 追问

- 框架升级后同一权重分数改变，应先对照哪些输入、输出和解析结果？

<a id="eva-002"></a>
### EVA-002 · 怎样评价文本生成质量？BLEU/ROUGE、PPL与人工评测如何组合？

**L1**

#### 答案

文本生成质量要按任务评价。BLEU 和 ROUGE 主要看与参考的词面重合，前者常用于翻译，后者常用于摘要；有明确答案时可以用精确匹配或 token F1，但需固定规范化、中文分词、别名、多参考和聚合规则。合理改写可能词面分低，复制参考中的错误也可能分高，所以它们不能包办事实、逻辑、指令遵循和可读性。

困惑度 PPL 是有效目标 token 平均负对数似然的指数，公式中的 V 是计入损失的位置集合，N_valid 是其数量。Teacher forcing 用真实历史 x_<t 预测下一 token；自由生成则接着自己的输出走，可能累积错误，两种条件不同。比较 PPL 要统一 tokenizer、语料、模板、损失掩码和上下文窗口或步长，不能跨分词粒度直接排名。低 PPL 也不保证回答有用。

我会建立未用于调参的提示集，按任务、语言、难度、长度和风险分层，并检查来源、改写和示例重叠。生成时固定模型、系统提示、聊天模板、检索工具、温度、top-p、top-k、输出预算与停止规则；随机任务多次运行并记录种子，但不承诺跨后端逐位一致。必要时预先声明多种解码协议，避免把解码改变当能力改变。

人工盲评再分准确、材料忠实、完整、指令遵循和可读性，用有锚点的标准、随机 A/B 顺序、平局与分歧复核。事实回查证据，代码运行测试，模型裁判用人工样本校准位置和冗长偏差，报告样本量、一致性与按问题统计的不确定度。不能用一个平均词面分或训练损失下结论，也不能凭高分就断言存在污染。

```math
\mathrm{PPL}=\exp\left(-\frac{1}{N_{\mathrm{valid}}}\sum_{t\in\mathcal{V}}\log p_\theta(x_t\mid x_{\lt t})\right),\qquad N_{\mathrm{valid}}=|\mathcal{V}|
```

#### 易错点

- 词面重合与真实历史下的预测损失，都不能代表全部开放生成质量；训练损失也不能验证泛化。
- 提示、检索、解码和输出预算变化都会混杂模型比较；高分也不能直接归因于未查证的训练污染。

#### 追问

- 预测困惑度相近但盲评偏好不同，怎样按事实、格式和可读性定位？
- 怎样区分正确改写的低重合、错误事实的高重合和参考背诵？

<a id="eva-004"></a>
### EVA-004 · 两个模型只差一个百分点，怎样判断提升可靠？

**L2**

#### 答案

两个模型差一个百分点，我会先看同一批题上各自错在哪里，再估计差值的不确定度。配对比较应一起重采样同一道题的两个结果，得到分数差的置信区间，必要时做配对检验；不能只算两个独立均值，也不能仅凭两个区间重不重叠判断提升。

例如模型 A 和 B 总分接近，但 B 修正了十道题又新错了九道，净收益只有一道，要看这种变化在不同样本和随机运行中是否稳定。同用户或同文档的多条题往往相关，应按用户或文档进行分组抽样；否则把相似样本当独立，区间可能过于乐观。随机任务还要考虑多次运行与种子差异。

实验方案最好预先确定，反复挑最佳参数和 seed 会抬高报告结果。统计显著也不等于值得上线，我会一起检查成本、延迟和重要分组。例如总体升分但关键安全或权限样本退化，仍需按业务阈值验收，不能让平均收益掩盖高代价错误。

#### 易错点

- 两个置信区间是否重叠不能代替差值检验，反复挑最好的随机种子也会抬高结果。

#### 追问

- 如果总分升但关键安全分组下降，你会怎样验收？

<a id="eva-005"></a>
### EVA-005 · 如何设计人工评测，降低标注分歧？

**L2**

#### 答案

人工评测先要让大家判断同一件事。我会把准确性、完整性、证据和可读性分开，给可操作标准与好坏锚点，先小规模试标，找出歧义后修规则，再让多位标注者独立评分并复核分歧。隐藏模型身份、随机候选顺序，并允许平局和无法判断，避免强迫每题选胜者。

例如答案语言流畅但金额错误，事实正确性应独立判错；普通用户喜欢简短，专家要求关键条件完整，可以依据产品目标分别定义偏好与质量，而不是把某个人的喜好当统一真值。专业事实需要可信资料与足够领域能力，缺少专家时应限制结论范围。

样本要覆盖真实流量和困难边界，报告来源、分层比例、权重、一致性与不确定度。只挑成功案例或中等分题会改变目标分布，即使胜率好看也不能代表全量。我会保留分歧原因，用它改标准和标签，而不是把分歧全部归为标注者问题。

#### 易错点

- 只挑中等分样本或成功案例会改变目标分布，须说明抽样与权重。

#### 追问

- 专家与普通用户偏好相反时，怎样定义业务评分标准？

<a id="eva-014"></a>
### EVA-014 · 代码生成的 pass@k 是什么，如何避免错误估计？

**L3**

#### 答案

Pass@k 是一道代码题采样 k 个候选，至少有一个通过测试的概率，再对题目平均。若实际生成 n 个、其中 c 个通过，n 不小于 k 时，可以用公式的组合数估计；它等于一减去随机选 k 个全部失败的比例，n−c 小于 k 时就是一，计算上可用稳定乘积避免大组合数溢出。

这个标准估计以每题固定生成分布与独立采样为前提，不能把观察到的 pass@1 直接塞进 1−(1−p)^k 当作无偏估计。若根据前面的测试结果继续改代码、自适应搜索或去重，候选生成协议已经不同，需要另行定义评测。温度提高可能增加候选多样性，改善 pass@100，却让单次命中变差。

代码正确性靠可执行测试，BLEU 无法判断两段等价代码。比较要固定采样次数、解码、测试、超时、沙箱和依赖，并检查测试覆盖。Oracle pass@k 只说候选中存在正确解，不代表产品能选中它；实际系统还需候选选择或验证，所以也应报告用户最终拿到的解是否通过。

```math
\widehat{\mathrm{pass@}k}=1-\frac{\binom{n-c}{k}}{\binom{n}{k}},\qquad n\geq k
```

#### 易错点

- 候选中至少有一个正确解，不代表用户最终拿到正确解，还需选择或验证。

#### 追问

- 为什么提高温度可能提升 pass@100 却降低 pass@1？

<a id="topic-3"></a>
## 幻觉与可信度

<a id="eva-003"></a>
### EVA-003 · LLM-as-a-Judge 有哪些偏差，如何校准？

**L2** · 深势科技

#### 答案

LLM-as-a-Judge 是让模型按评分标准评价答案，能降低开放任务的评测成本，但它也可能受候选位置、长度、风格、提示和领域能力影响。我会隐藏被评模型身份，给明确维度、锚点和可核验参考，固定裁判模型与提示版本，保留评分证据，不只记录一个数字。

例如把同一对回答交换 A/B 顺序，如果结论经常跟位置走，就说明存在偏差；写得更长也不该自动得更高分，需检查有没有多提供正确内容。数学优先核对参考，代码优先执行测试，再用人工分层样本检查裁判的误报、漏判及领域差异。

来自同一厂商或风格相似可能带来偏好，但原论文的自我偏好实验不足以证明所有裁判必然偏爱自己。我会实际测身份隐藏、顺序交换和风格控制后的变化，并报告不确定样本。裁判与人工一致性也不是永恒属性，换领域或版本后应重校准，不能把裁判分数当无误真值。

#### 易错点

- 原论文不能确定所有裁判都有自我偏好，不应把可能的风格偏差说成必然结论。

#### 追问

- 裁判和被评模型是同一家时，你如何检验风格偏差？

<a id="eva-006"></a>
### EVA-006 · 如何区分事实幻觉与上下文不忠实，怎样检测和缓解？

**L2**

#### 答案

事实幻觉是陈述错误或缺乏事实支持，上下文不忠实是回答与给定材料矛盾或超出依据。两者要先确定证据范围：一个外部事实可能是真的，却超出了“只依据材料”的任务；忠实复述错误材料，也不一定真实。我会把实体、数字、关系和引用拆成可核验陈述，区分无支持、矛盾、过期与暂时不可验证。

例如资料说旧政策、现实已更新，回答应说明冲突和适用时间，而不是悄悄更正却让用户误以为来自原文。检测可以用可靠来源、专门回归集与人工抽查，覆盖误导前提、缺证据和相互冲突材料。能识别别人答案的幻觉，也不代表生成时永不出错。

SelfCheckGPT 对同一问题多次采样，通过语义、问答或自然语言推断等方式比较句子的一致性，用作黑盒风险信号。但多次回答也可能稳定地犯同一个错，一致性不能代替事实核验，还要算采样成本。事实核心采样则在一句话内逐步降低 top-p、保留下限，并在新句重置，调整随机性与多样性；它没有查证知识，只是解码策略。

我会在目标任务上重新测检测与缓解效果。低温、更大模型或某个基准高分都没有事实保证，拒答、引用核验与证据覆盖仍需一起设计。

#### 易错点

- 常见基准只覆盖部分类型，低温或更大参数不保证事实正确。

#### 追问

- 如何评价模型纠正了资料中的错误，但没有解释证据冲突？

<a id="eva-007"></a>
### EVA-007 · 模型自报置信度可靠吗，怎样设计拒答阈值？

**L3**

#### 答案

模型自报“九成把握”不天然对应九成正确率。Token 概率表示下一词的分布，答案的语义置信和事实是否可信又是其他对象；回答语气犹豫，也可能只是学到的模板。先明确用什么信号，再用独立验证集上的正确性标签校准。

我会扫描拒答阈值，画覆盖率与错误率的关系，同时算漏答、错答代价和正确回答数量。高风险问题错答代价大，可以接受更低覆盖；普通低风险问答则可能更重视服务可用性。例如一个阈值让准确率提高，却拒绝了大半有效问题，不能只报告准确率说它全面更好。

检索证据、自检和多次采样都可以提供额外信号，但是否有用要实测，不能把一致性当真值。新领域、语料或模型版本变化后，应重新验证校准与分组表现。最终目标是可控地在回答和拒答之间取舍，而不是相信模型自己的置信数字。

#### 易错点

- 模型声称不确定也可能是模板行为，不代表具备准确的自我知识。

#### 追问

- 对高风险和低风险问题为什么应使用不同阈值？

<a id="topic-4"></a>
## 安全与鲁棒性

<a id="eva-008"></a>
### EVA-008 · 安全评测如何兼顾越狱成功率与过度拒答？

**L2**

#### 答案

安全评测要同时测违规和误拒，否则一个模型全部拒答也能显得很安全。我会构建恶意请求与语义接近的合法请求成对样本，按风险、语言、轮次、模态和工具环境分层，固定攻击次数、预算和判定规则，一起报告攻击成功率、误拒率及无法确定的情况。

成功判断看实际内容和行动，例如是否泄露、是否执行越权工具，而不是看出现几个敏感词或拒答是否礼貌。单轮文本覆盖不了多轮诱导、图片中的指令和工具副作用，因此需要与部署形态相匹配的测试。正常边界样本也能区分语义判断与简单关键词拦截。

零次攻击成功只说明这批样本和预算下未成功，不能证明没有漏洞。改了拒答措辞后，应重新测真实泄露与违规是否下降，以及合法任务是否退化。我会把发现的新失败加入回归，同时保留未见攻击做独立验证，避免只适应固定题库。

#### 易错点

- 零次成功只是当前测试集与预算结果，不能证明不存在漏洞。

#### 追问

- 拒绝表达更礼貌了，但泄露率没下降，如何判断改进？

<a id="eva-009"></a>
### EVA-009 · 如何构建红队测试而不只刷固定攻击集？

**L3**

#### 答案

红队测试先明确要保护的资产、攻击者能控制什么和怎样才算成功，再构造多样攻击。我会覆盖直接请求、外部恶意材料、跨轮组合和工具权限，使用人工、规则和模型生成候选，保存目标、输入、预算、环境和完整轨迹，便于复现。

例如针对泄露资料，攻击不应只换同一句话几十种写法，还要改变入口、语言、上下文和数据流。模型可以帮助扩候选，自动裁判则要人工抽查，避免把模型口头声称成功当成实际泄露。攻击模型与防御模型的效果也要分别看，不能因为候选很多就认为覆盖充分。

我会按失败类型去重，把新类别加入回归，留下未见攻击验证防御泛化，在同等预算下比较成功率和覆盖。红队擅长找问题，但找到几例或没有找到，都不能完整量化风险；结论应说明测试资产、攻击范围和未覆盖场景，而不是靠固定公开攻击集给万能安全承诺。

#### 易错点

- 红队发现问题不等于全面量化风险，未测领域要明确列出。

#### 追问

- 如何避免同一失败模板大量重复导致覆盖率虚高？

<a id="eva-010"></a>
### EVA-010 · 训练数据泄露与 RAG 越权泄露如何区分？

**L2**

#### 答案

训练数据泄露和 RAG 越权泄露的根因不同。前者是模型参数记住内容，被查询诱导重现；后者是检索、缓存或工具把用户无权访问的资料送进模型。训练侧要考虑数据最小化、去重与记忆泄露测试，访问侧要做身份、权限和缓存隔离，不能用同一段拒答提示解决。

我会先追踪答案的来源：用户输入、历史上下文、检索结果和工具路径有没有该内容。没有接入某资料仍输出，并不能立即证明来自训练，也可能有其他上游输入或公开来源。测试可以用受控标记 canary 和访问矩阵验证，不应为测试扩散真实敏感内容。

例如撤回用户数据，要分别处理原文、索引、缓存、日志、长期记忆与训练使用记录。删除向量索引不代表删除参数记忆，模型侧可能还需其他遗忘或重新训练措施，并验证效果。两类生命周期和检测边界都要单独说明，避免把输出个人信息直接等同于训练泄漏。

#### 易错点

- 输出里有个人信息不自动证明来自训练语料，须排查输入和工具路径。

#### 追问

- 企业要求撤回某用户数据时，哪些层需要分别处理？

<a id="eva-012"></a>
### EVA-012 · 怎样评估 prompt 扰动、多语言和分布外鲁棒性？

**L2**

#### 答案

鲁棒性评测要区分表达改变与事实改变。语义等价改写、拼写噪声和格式变化用于看同一问题能否稳定回答；事实改变的对照则检查模型会不会随证据更新。若翻译改了含义或加入更难条件，就不能当成纯扰动，变换后的标签要人工确认。

我会先固定任务提示和解码，再分别改变语言、领域、长度与模板，按组报告性能和成本。例如英文正确、中文错误，要检查知识覆盖、分词、检索和答案解析，而不是立即归因于某一个模块。检索或安全关键词规则也可能制造表面上的模型退化。

总体均值容易掩盖少数语言、长尾实体或长输入的失败，所以应看最弱组和重要业务组。多模板测试还要控制示例、预算和语义一致性。结论应限定扰动类型与范围：在几种改写下稳定，并不证明所有域外输入都可靠。

#### 易错点

- 语义变了的样本不是纯鲁棒性测试，需人工确认变换标签。

#### 追问

- 翻译后性能下降，怎样分辨知识覆盖、检索和分词编码的问题？
