## 评测协议与基准

<a id="eva-001"></a>
### EVA-001 · 如何避免训练数据污染评测集？

**L2** · 字节跳动

#### 答案

训练与测试的题目或答案重叠会夸大泛化能力，近重复、翻译和模型改写也可能造成污染。应按来源、实体、用户或时间划分数据，结合精确和语义去重，保留新鲜私有测试与版本；仅做 n-gram 去重不足以发现语义改写或答案泄漏。

调参验证集与最终测试集需分开，防止反复查看测试结果选方案。合成数据的生成提示也可能包含公开题，应追踪源问题和教师输出。训练语料未知时需说明检测边界：未检出重叠不证明无污染，只改几个词也不能将公开题视为新基准。

#### 易错点

- 检测不到重叠不等于证明无污染；不能只改几个词就称新基准。

#### 追问

- 项目数据量小，按用户拆分后类别不平衡怎么处理？

<a id="eva-011"></a>
### EVA-011 · MLLM 评测如何区分感知、OCR 与推理错误？

**L2**

#### 答案

MLLM 答错可能源于 OCR、对象定位、图表感知、跨模态关系或推理。应按图像类型及能力拆分样本，分别报告 OCR、计数、空间关系、图表和专业多学科推理表现，并固定分辨率、图片数及答案解析规则。

通过原图、裁剪和人工文本转写等消融定位瓶颈；text-only 与真实图像输入的比较，可检查语言先验猜测。替换或打乱图像后答案不变，可能提示视觉依赖不足，但需排除多答案歧义。单一综合榜单不能覆盖视频、定位或高分辨率读图的全部能力。

#### 易错点

- 一个综合榜单不能代表视频、定位或高分辨率读图的全部能力。

#### 追问

- 原图错、人工 OCR 文本对时，应优先改哪一环？

<a id="eva-013"></a>
### EVA-013 · 如何验证 prompt 优化确实有效？

**L2** · 字节跳动

#### 答案

Prompt 优化应作为有验证集的实验：定义可观察目标，固定模型和解码，每次改变明确因素，在留出样本上比较，不能凭单个演示变好断言泛化。格式、长度和关键词可规则检测，事实或语义质量需其他验证。

JSON 合法性、指定字段及字数等可执行约束使用稳定 parser；任务成功与单项指令遵循分别统计，多个约束全部满足才计为整题通过。版本化模板与 few-shot 样例，防止样例和测试内容重叠。更多约束可能相互冲突，降低 temperature 也不必然缩短输出。

#### 易错点

- prompt 中加入更多约束可能互相冲突，temperature 降低不必缩短输出。

#### 追问

- 同 prompt 训练集涨分、留出集退化时如何处理？

<a id="eva-015"></a>
### EVA-015 · 线上如何监控、验收并回归 LLM/Agent 系统？

**L2**

#### 答案

离线通过后，线上仍需观测任务成功、拒答、工具错误、事实反馈、时延与成本。保存可复现版本和 trace，记录请求、检索、工具及结果；敏感字段应最小化记录并控制访问。点击率受曝光、用户群及界面变化影响，不能直接当作答案正确率。

按风险和流量分层抽检，将新失败案例加入回归，同时保留独立验收集。重复 trial 检查随机性，故障注入验证限流、断线和恢复。发布前后同口径比较能力、合规边界及效率，并设置退化回滚条件，避免平均分掩盖新增问题。

#### 易错点

- 把线上点击率当答案正确率会受曝光、用户群与界面变化混杂。

#### 追问

- 线上成本骤增但准确率没变，应怎样定位？

<a id="eva-016"></a>
### EVA-016 · MMLU、BIG-bench/BBH、GSM8K 与 HumanEval 分别测什么，怎样读榜单？

**L2**

#### 答案

基准反映特定数据和协议下的任务能力。MMLU是57学科的选择题，偏向知识与学科问题解决；BIG-bench覆盖多种任务，BBH是其中较困难的一组任务，不能把两者分数混作同一指标。GSM8K偏数学应用题，需按规则提取最终答案；HumanEval用函数编程题与测试评估代码功能，pass@k还依赖采样次数及解码设置。

选择题可比较选项log-likelihood，也可让模型生成答案，但prompt、选项顺序、few-shot例子和评分协议不同会改变结果。推理任务还应报告回答/测试时算力预算，不能把更长思考或更多采样的收益全归于参数规模。

榜单需要核对模型版本、模板、数据split、生成设置、污染与题目重复。综合平均会掩盖业务短板，高分也不意味着长上下文、事实拒答、工具执行或多语言都强。用这些基准定位候选，再以独立业务集和分层错误分析验收。

#### 易错点

- 排行榜同名基准不一定用了相同few-shot、CoT、答案解析与采样预算。

#### 追问

- 选择题log-likelihood分高，生成式回答却经常不遵守格式，应如何评价？

<a id="eva-017"></a>
### EVA-017 · AgentBench、WebArena、GAIA、SWE-bench 与 τ-bench 怎样评价 Agent？

**L2**

#### 答案

Agent基准提供任务、交互环境和验收规则，关注实际完成而非模型自报成功。AgentBench涵盖多个环境的推理决策；WebArena在可复现网站任务中检验网页操作与状态达成；GAIA的问题常需组合检索、文件/多模态和工具；SWE-bench让模型修复真实代码仓库问题并执行测试；τ-bench关注工具、模拟用户与领域政策的交互。

环境状态型验收、最终答案匹配和代码测试不是同一种评分。任务初态、网络/工具版本、权限与budget必须固定，动态网络或模拟用户随机性也需记录，不能说所有基准都完全离线或绝对确定。环境失败应与Agent决策失败分开。

报告任务成功率、重复运行稳定性、调用/成本、延迟、越权和恢复表现。代码测试通过可能不覆盖全部业务行为；单次成功可能来自幸运采样。对于真实产品，应选与你的动作空间和失败代价一致的任务，而非用一个榜单代表Agent通用水平。

#### 易错点

- 文档检索问答基准的答案正确率不能替代网页/代码Agent的环境状态验收。

#### 追问

- 同一Agent多次运行时成功率差异大，怎样设计重复试验和置信区间？

<a id="eva-018"></a>
### EVA-018 · 怎样设计可靠的 benchmark，并用评测框架建立可复现验收？

**L2** · 腾讯

#### 答案

评测框架负责加载任务、调用模型、解析输出与汇总指标，不替代任务定义。LM Evaluation Harness把标准任务与模型后端分离，适合控制few-shot、log-likelihood/生成协议和答案过滤；RAG/Agent还需要证据、工具轨迹及环境结果验证，不能仅复用文本匹配分数。

固定任务定义/数据版本、模型checkpoint、tokenizer/template、生成预算与停止规则，保存原始输出及评分中间结果。明确每个指标的分母、失败/超时处理与任务权重，按语言、难度、长度等分层；将实验开发集与最终验收集分开。

新增模型或prompt先跑小批次确认输入与答案解析，再运行冻结回归集。重跑随机任务以估计不确定度，并抽查评分器与人工结果的一致性。对RAG记录所用证据版本，对Agent重置初态并校验副作用；最后核对业务阈值、成本与延迟，而非只保存一个平均分。

一个好的benchmark还应清楚定义目标能力和适用人群，覆盖真实任务与难例，并给出一致、可复核的标签和评分规则。训练/开发/验收数据要分开，控制污染、模板捷径与语言先验；对多模态设置遮图、换图、人工转写等对照，检查题目是否确实依赖视觉。报告分任务得分和置信区间，识别饱和、标注歧义及成本差异；冻结榜单之外保留新域回归，避免把反复调过的测试集当独立验证。

#### 易错点

- 评测脚本运行成功不代表协议一致，模型输出解析错误可造成虚假零分或高分。

#### 追问

- 框架升级后同一checkpoint分数改变，应优先比对哪些原始结果？

## 指标与统计检验

<a id="eva-002"></a>
### EVA-002 · 怎样评价文本生成质量？BLEU/ROUGE、PPL与人工评测如何组合？

**L1**

#### 答案

文本生成评测先按任务选择指标，再在固定生成协议下比较输出，结合独立分层问题、事实或执行核验与盲评。BLEU/ROUGE 反映参考文本重合，teacher-forced PPL 反映真实历史下的预测概率，两者均不足以代表自由生成质量。

有明确参考答案的任务可使用 EM/token F1，但需固定规范化、中文分词和别名处理。BLEU 原用于翻译，ROUGE 常用于摘要；报告具体变体、tokenizer、corpus/sentence 聚合及多参考处理。多参考能覆盖部分合理改写，词面重合仍不保证事实、逻辑或指令遵循，不能将任务内适用性外推为通用 LLM 质量。

Teacher-forced PPL 是有效目标 token 平均负对数似然的指数，用评测文本的真实历史 $`x_{<t}`$ 预测 $`x_t`$；自由生成会将自己的输出纳入后续历史，两者条件分布不同。比较 PPL 须统一 tokenizer、数据、模板、loss mask 和上下文窗口/stride，不能直接跨分词粒度排名。低 PPL 不保证回答有用、事实正确或能从多轮错误中恢复。

建立未用于调参的 held-out prompt 集，按任务、领域、语言、难度、长度和风险分层，报告各层及按目标流量加权的结果。检查训练或调参材料的重复、近似改写与模板泄漏，加入新写问题和表述变体；背诵参考能抬高词面分数，但单个高分或低 PPL 不能证明污染或泛化，训练数据未知时需明确核验边界。

自由生成须固定并记录模型/checkpoint、system prompt、chat template、检索与工具条件、`temperature`、`top-p`、`top-k`、最大输出长度和停止规则，明确资源预算。随机采样使用多次 trial 并记录 seed，但 seed 不保证跨后端逐 bit 重现；必要时比较多个预先声明的解码协议，避免将解码变化当作模型能力变化。

人工评测以带锚点的 rubric 分别评价准确性、材料忠实性、完整性、指令遵循和可读性，隐藏模型身份、随机 A/B 顺序，允许平局、无法判定及分歧复核。事实任务核查证据，代码执行测试，LLM judge 校准位置与冗长偏差；报告样本量、一致性及按 prompt 统计的不确定度，不能用单个平均词面分数代替全部结论。

```math
\mathrm{PPL}=\exp\left(-\frac{1}{N_{\mathrm{valid}}}\sum_{t\in\mathcal{V}}\log p_\theta(x_t\mid x_{\lt t})\right),\qquad N_{\mathrm{valid}}=|\mathcal{V}|
```

#### 易错点

- 将BLEU/ROUGE或teacher-forced PPL当作所有开放生成任务的统一质量，或只看训练loss验证泛化。
- 一边改变prompt、检索、解码或输出预算一边比较模型，或把未查证的训练污染当成高分的唯一解释。

#### 追问

- 两个模型PPL相近，但盲评偏好明显不同，应怎样分层定位原因？
- 如何区分正确改写导致低ROUGE、事实错误导致高ROUGE，以及对参考答案的背诵？

<a id="eva-004"></a>
### EVA-004 · 两个模型只差一个百分点，怎样判断提升可靠？

**L2**

#### 答案

一个百分点的差异是否可靠，需结合样本量和逐题配对差异，报告分数差的置信区间，必要时做配对检验或 bootstrap。比较同一测试题上的两个模型时，应共同重采样它们的结果，而非只比较两个独立均值；区间是否重叠也不能替代正确的差值检验。

重复题、同用户或同文档样本往往相关，应按用户或任务进行 cluster 级抽样。多次调参、不同随机种子及反复挑选最佳 seed 也会影响结论。统计显著不等于业务收益，需同时报告成本、延迟和关键分组退化。

#### 易错点

- 区间是否重叠不能替代正确的差值检验，反复挑最好 seed 也会偏高。

#### 追问

- 如果总分升但关键安全分组下降，你会怎样验收？

<a id="eva-005"></a>
### EVA-005 · 如何设计人工评测，降低标注分歧？

**L2**

#### 答案

人工评测应为准确性、完整性、证据和可读性等维度制定 rubric 与锚点样例，隐藏模型身份并随机展示顺序。先小规模试标、修订含糊规则，再独立多标注与分歧仲裁；保留平局和无法判断，避免把个人偏好当作统一真值。

分层抽样应覆盖普通和困难案例，说明样本构成、抽样权重、一致性与不确定度。事实正确性需要可信材料支持，并与偏好评价分开。专家不足时限制领域结论；只挑成功或中等分样本会改变目标分布，不能只报告一个总胜率。

#### 易错点

- 只挑中等分样本或成功案例会改变目标分布，须说明抽样与权重。

#### 追问

- 专家与普通用户偏好相反时如何制定业务 rubric？

<a id="eva-014"></a>
### EVA-014 · 代码生成的 pass@k 是什么，如何避免错误估计？

**L3**

#### 答案

Pass@k 衡量每题采样 $`k`$ 个候选至少一个通过测试的概率，再对任务取平均。生成 $`n\geq k`$ 个候选，其中 $`c`$ 个通过时，可使用组合数估计；若 $`n-c<k`$，估计值为 1，实际计算可用稳定乘积避免大组合数溢出。

标准无偏估计解释以每题固定生成分布、独立采样为前提，不能直接把经验 pass@1 代入 $`1-(1-p)^k`$ 当作无偏估计。自适应搜索、去重或依赖先前测试结果生成候选时，需另行定义评测。

通过条件是可执行功能测试，BLEU 不能衡量等价代码的正确性。比较须固定采样与测试预算，并记录覆盖、超时、沙箱和依赖版本。Oracle pass@k 也不等于用户实际得到正确答案的概率，部署仍需选择或验证候选。

```math
\widehat{\mathrm{pass@}k}=1-\frac{\binom{n-c}{k}}{\binom{n}{k}},\qquad n\geq k
```

#### 易错点

- oracle pass@k 不等于用户拿到正确答案的概率，部署仍需要选择/验证候选。

#### 追问

- 为什么提高温度可能提升 pass@100 却降低 pass@1？

## 幻觉与可信度

<a id="eva-003"></a>
### EVA-003 · LLM-as-a-Judge 有哪些偏差，如何校准？

**L2**

#### 答案

LLM-as-a-Judge 能降低开放回答评测成本，但会受候选位置、长度、提示和领域能力影响。应使用盲测 rubric、可核验参考与人工金标准，固定裁判模型和提示版本，并记录评分理由与证据；数学和代码优先使用参考或执行验证。

随机候选顺序、交换顺序做双向比较可缓解位置偏差，冗长回答仍应按内容质量评分。通过人工分层样本估计 judge 的召回、误报和领域差异，报告不确定样本与系统性误判。原论文的 self-enhancement 实验不足以证明所有裁判都必然偏爱自身回答。

#### 易错点

- 原论文 self-enhancement 实验不足以下确定结论，不能笼统声称所有裁判必偏爱自己。

#### 追问

- 裁判和被评模型是同一家时，你如何检验风格偏差？

<a id="eva-006"></a>
### EVA-006 · 如何区分事实幻觉与上下文不忠实，怎样检测和缓解？

**L2**

#### 答案

事实幻觉指陈述缺乏事实支持或错误，上下文不忠实指输出与给定材料矛盾或超出其依据。先明确证据范围，再分解实体、数字、关系和引用逐项核验：正确外部事实也可能超出任务限定材料，忠于错误材料的答案也未必真实。

区分 unsupported、contradicted、不可验证和过期等情况，避免粗略归为同一种错误。使用可靠来源复核真实业务案例，覆盖缺证据、误导前提和冲突文档，并用专门数据集做回归。幻觉识别能力不等于生成时从不幻觉，局部基准、低温或更大参数也不提供事实正确性保证。

SelfCheckGPT 对同一问题多次随机采样，再用语义相似度、问答、NLI 或模型判别比较待测句子与各样本的一致性，得到幻觉风险分数，适用于只有文本输出的黑盒模型。多次回答可能稳定重复同一个错误，因此一致性只是检测信号，不能替代外部事实核验；还需考虑采样次数、成本和不同采样设置。

事实核心采样（factual-nucleus sampling）是在生成一句话时逐步降低 top-p 阈值，设衰减下限，并在新句开始时重置，以减少句子后半段的随机性，平衡事实性、多样性与复读。它改变解码候选集合，不会查询事实或修复错误知识；论文中的收益需在目标任务上重新验证。

#### 易错点

- 常见基准只覆盖部分类型，低温或更大参数不保证事实正确。

#### 追问

- 如何评价模型纠正了资料中的错误，但没有解释证据冲突？

<a id="eva-007"></a>
### EVA-007 · 模型自报置信度可靠吗，怎样设计拒答阈值？

**L3**

#### 答案

模型声称“九成把握”不天然对应九成正确率，表达不确定也可能只是模板行为。Token 概率、答案语义置信和事实可信是不同对象，应明确置信信号，再结合验证集与正确性标签进行校准。

按风险选择拒答阈值，画覆盖率—错误率曲线，同时评估未答率、错答成本和正确率；拒答减少错误，也降低服务覆盖。检索证据、自检和多样采样可以提供信号，但有效性需实测。新领域或分布变化后重新验证，不能只看平均准确率。

#### 易错点

- 模型声称不确定也可能是模板行为，不代表具备准确的自我知识。

#### 追问

- 对高风险和低风险问题为什么应使用不同阈值？

<a id="topic-4"></a>
## 安全与鲁棒性

<a id="eva-008"></a>
### EVA-008 · 安全评测如何兼顾越狱成功率与过度拒答？

**L2**

#### 答案

安全评测既检查恶意请求及攻击改写下的违规，也检查语义相近的正常问题是否被误拒。使用恶意与合法边界相近的成对样本，区分语义判断和关键词拦截；按风险类别、语言、轮次和工具环境分层，固定攻击预算与判定标准，联合报告攻击成功率、误拒率和不确定样本。

成功需核验实际内容或行动，不能只统计敏感词。单轮文本测试不能覆盖多轮诱导、图像输入或工具副作用；零次成功也只代表当前测试集和预算下的结果，不能证明不存在漏洞。优化礼貌拒答模板还需验证实际泄露或违规是否下降。

#### 易错点

- 零次成功只是当前测试集与预算结果，不能证明不存在漏洞。

#### 追问

- 拒绝表达更礼貌了，但泄露率没下降，如何判断改进？

<a id="eva-009"></a>
### EVA-009 · 如何构建红队测试而不只刷固定攻击集？

**L3**

#### 答案

红队先定义资产与威胁模型，再设计人工、规则及模型生成的多样攻击，明确成功条件并记录复现轨迹。覆盖直接请求、间接资料、跨轮组合和工具权限边界；模型可生成候选攻击，自动裁判仍需人工抽检，防止伪成功。

将新失败类别加入持续回归，同时留出未见攻击验证，避免系统只适应公开模板。相同目标下比较攻击预算、成功率、覆盖度与可复现性，并独立评估攻击和防御模型。发现问题不等于全面量化风险，应明确未测领域。

#### 易错点

- 红队发现问题不等于全面量化风险，未测领域要明确列出。

#### 追问

- 如何避免同一失败模板大量重复导致覆盖率虚高？

<a id="eva-010"></a>
### EVA-010 · 训练数据泄露与 RAG 越权泄露如何区分？

**L2**

#### 答案

训练数据泄露来自参数化记忆被查询诱导重现，RAG 越权泄露则来自检索、缓存或工具授权把无权访问的资料交给模型。前者需要数据最小化、去重和泄露测试等防护，后者必须在访问层隔离，不能用同一个拒答 prompt 解决。

归因需排查输入与工具路径；未接入某资料仍复现，可能来自记忆，也可能来自其他上游输入，输出个人信息不自动证明训练泄漏。测试使用可控 canary 和访问矩阵，避免扩散真实敏感信息。删除索引不等于删除参数记忆，两类生命周期应分别追踪。

#### 易错点

- 输出里有个人信息不自动证明来自训练语料，须排查输入和工具路径。

#### 追问

- 企业要求撤回某用户数据时，哪些层需要分别处理？

<a id="eva-012"></a>
### EVA-012 · 怎样评估 prompt 扰动、多语言和分布外鲁棒性？

**L2**

#### 答案

鲁棒性评测应分别考察语言、领域、长度和输入表达变化，构造语义等价改写、拼写噪声与格式变化。等价扰动用于测一致性，事实改变的对照用于测模型是否随证据正确更新；真正更难或语义改变的任务需单列，不能当作纯扰动，并人工确认变换后的标签。

先统一同一任务的 prompt 和解码，再测试多模板敏感性，按组报告性能与成本。总体均值不能掩盖少数语言、长尾实体或长上下文退化，还需检查 parser、检索和安全策略是否引入了非模型问题。

#### 易错点

- 语义变了的样本不是纯鲁棒性测试，需人工确认变换标签。

#### 追问

- 翻译后性能下降如何区分知识缺失、检索和 tokenizer 问题？
