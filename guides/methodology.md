# 采集与核验方法

[返回首页](../README.md) · [来源目录](../SOURCES.md)

本版的目标是覆盖 LLM/MLLM 面试知识体系，同时让题目线索可以追溯。检索日期是 2026-10-02（Asia/Shanghai），不代表每篇帖子发布于这一天。

## 检索渠道与纳入规则

检索小红书、知乎、牛客、GitHub 公开题库与技术社区。使用“公司 + 大模型/多模态/算法/Agent + 面经/面试/手撕”等组合发现候选，按主题继续检索。实际查询与可读情况分别记录在 [工程组](../research/engineering.md)、[基础组](../research/core.md)、[应用组](../research/alignment_rag.md)、[多模态组](../research/multimodal.md)。

纳入能够说明具体提问或备考主题的内容；不纳入不相关求职营销、招聘薪资推测、未读付费正文。社区中的“某公司真题”“必问”“高频”不会自动继承为事实，也不把同一帖子多次转载计为独立面试样本。

没有访问登录账号、评论区、私信或私人资料。小红书原帖访问失败后保留二手线索和待核链接，不绕过登录或付费墙。

## 证据分层

| 字段 | 含义 | 能证明什么 |
|---|---|---|
| `reported_question` | 已读社区正文明确出现该提问 | 该页面报告了问题；不能证明真实发生 |
| `reported_topic` | 已读正文提及主题，题目经重组 | 该主题出现；不能声称逐字原题 |
| `search_snippet` | 只能读搜索摘录 | 摘录出现问题/主题，正文上下文未核验 |
| `secondary_report` | 小红书等原帖仅有可读二手报道 | 报道声称该题出现，原帖未确认 |
| `editorial=true` | 无社区题目线索 | 编辑为知识覆盖或练习设计 |

同一题可以有多个社区线索，但 `reference_ids` 仅指向技术依据，与题目采集来源分开。答案为独立讲解，不代表面经作者当时的回答。

## 访问范围

| `source.access` | 含义 |
|---|---|
| `full` | 相关公开正文实际可读；不是来源真实性或所有细节已验证的认证 |
| `partial` | 公开前段或部分内容可读，另有付费/截断 |
| `snippet` | 搜索摘录或论文摘要可读，完整正文未读 |
| `blocked` | 正文无法访问，只保留追索链接，不作为题目证据 |

摘要只用于支持它实际说出的事实。计算公式优先核对全文、官方实现或文档；某些代码题的公式是独立数学推导，并以性质测试验证。每条记录的 `notes` 应说明具体读取范围。

## 技术答案核验

1. 根据主题选择原始论文、项目官方实现与官方文档，核查定义、目标函数、张量形状与版本。
2. 分开写标准方法与变体，避免把实现选项当成普遍定义。重点核查 DPO 的 sequence logprob、GRPO 的组内方差和长度偏差、GQA 的 KV 头数、ZeRO 状态假设、多模态位置编码版本。
3. 公式注明变量和假设；显存公式区分持久状态、激活、缓存和峰值，性能结论注明硬件/长度/并发依赖。
4. 代码用边界与独立对照测试；不可执行的可选依赖明确标记，不能说全部测试通过。
5. 分工互审并记录具体修复，再统一检查 ID、来源边、分类、内部链接和生成文件一致性。

来源链接数量不等于所有句子都在该链接中逐字出现；工程方案、沟通方法与反例包含编辑分析，属于有依据的建议，不是论文的实验结果。

## 覆盖与局限

这是检索样本与体系补充形成的静态题库，不是各家公司的完整题单，也不是统计抽样调查。没有根据点赞量、转载量或网络标题给出“实际面试出现率”。L1/L2/L3 和学习顺序均为编辑判断。

模型和协议会更新；答题时应说清版本。以代表性模型解释机制，不作截至采集日期“最强模型”的排行榜承诺。

单页只保留少量主题与必要的短引用，答案独立综合；不镜像或批量复制社区长文、课程、付费题解、论文图表或模型权重。来源版权不因链接被收录而改变。
